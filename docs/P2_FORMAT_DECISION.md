# P2 统一材料记录路线裁决

日期：2026-09-28。总控选择 **A：统一 material-records.json，旧包一次性补旁路元数据**。此为路线与任务卡调整裁决，不是对真实材料目录的写入授权。

## 生产与读取职责

材料根级 `material-records.json` 为统一格式，每类材料根一份，引用根内相对文件。保留现有 v1 兼容性，必要的新字段必须可选、白名单、有界且有明确来源。现有三个 ZIP 不重制、不解压、不覆盖；原 release-record.json、校验清单及说明原字节保留。

今后由实际打包脚本在产物成功生成后取得文件事实并生成记录。AI 可编写、调用和核对脚本，不能猜测构建来源、兼容范围或测试通过。Git 提交只是源码检查点，不自动等同于已构建包；新提交不应自动生成材料记录。实际接入业务打包脚本属于单独后续任务，不在本轮修改业务源码。

管理软件的 P2 接入/刷新继续只读，不因新增包自动写入或初始化材料记录。没有记录仍显示文件及待识别状态。将来 P4 可增加主动触发的草稿初始化和受控归档；该功能不提前加入 P2。

## 旧包与未知事实

针对用户指定根下的两份安装包、一份升级候选包，先在工具自己的工作区生成两份迁移草稿和逐字段来源清单。只映射可追溯的记录事实；构建提交未知继续未知，升级 directFrom 未声明就省略，不能写空数组或从 rc9→c4 猜最低支持。状态为候选，安装/升级未验收；历史登记 SHA-256 与本次校验结果严格分开。不得填未执行的验证通过。

记录字段来源至少在迁移清单中可审查，前端不得把新记录生成时间冒充旧包构建或验证时间。读取不到的字段保持未知，不为满足格式而补造版本/修订。

## T04 改写授权与验收边界

允许阶段控制改写 `docs/stages/P2/P2-T04.md`、阶段方案、索引、格式说明与策略文档，取代尚未实施的旧格式长期适配方案。先完成统一格式必要的只读展示、小型临时夹具验证、真实来源只读核对、迁移草稿和精确变更清单；不开发永久双格式适配器或通用迁移框架。

真实目录写入尚未授权。草稿准备完成后，把两个目标文件的准确路径、完整内容、来源和仅新增文件的影响交用户确认。用户先前授权为查看真实目录及讨论改造，不能解释为同意实际写入。不得提前创建真实记录文件；如目标已存在，停止覆盖，先比较并报告。

如后续获准执行迁移，应与产品只读逻辑分离：只新增已审查的两份记录；操作前重新核对目录身份与来源未变化，冲突不覆盖；失败不动原包。记录两文件各自结果，不假设跨两个目录的写入天然原子。失败清理只限本次创建的、内容仍匹配的文件。

真实材料层级造成 partial 的问题独立处理：选择覆盖所需材料的关联根或调整有界扫描契约，不取消上限，不把 partial 伪装 complete。草稿引用必须在当前安全扫描范围可见。

P2 最终验收仍须真实记录读取、候选/未知事实展示、最低支持摘要与详情一致、材料未被读取逻辑修改，并由总控独立验收。未授权迁移时可以完成代码和草稿，但不得宣称真实统一接入已完成。不启动 P3/P4，不提交、推送或自动重打业务包。
