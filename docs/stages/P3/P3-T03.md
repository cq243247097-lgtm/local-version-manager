# P3-T03 任务卡：本地提交专用 HTTP 接口

本卡仅在 P3-T01/T02 均经阶段主控 **PASS** 后交 Gemini。Gemini 型号由用户选择，阶段主控审核，总控在整阶段交接后独立验收。先核对 T02 的最终文件指纹与当前工作区。目标是把已经验收的提交核心接入已登记项目的安全 API；不重新设计核心、不做前端或其他 Git 操作。

## 文件所有权

独占 `server/app.js`，必要时最小修改 `server/security.js`；只新增/修改直接相关 `tests/git_commit_api.test.js`、`tests/security.test.js`、`tests/api.test.js`。不改 `server/git/*`，除非发现 T02 接口缺陷并交阶段主控决定回 T02；不改 `server/config.js`、`frontend/*`、`preview.mjs`、材料模块、P1/P2/总控文档与真实业务仓库。HTTP 持久操作目录需从当前配置路径派生或注入临时路径，不能硬编码到业务仓库。

## 接口契约

1. 仅为已登记项目 ID 开启专用提交候选/预览/确认/操作结果路由。`GET` 候选/结果只能做只读 Git/本工具记录读取，绝不创建预览票据、锁、Git 对象或更新索引；如候选计算需写临时索引，改为显式 `POST` 检查并如实描述，不偷放在 GET。预览 `POST /api/projects/:id/commit/preview` 仅接收候选 ID 列表和提交说明；确认 `POST /api/projects/:id/commit/confirm` 仅接收票据和操作 ID。已登记 ID 由配置持锁/重读适当核对后得到 `repositoryPath`，客户端不传路径、命令、选项、ref 或 remote。
2. 写相关 POST 使用唯一精确 Host、必须同源 Origin、拒绝 cross-site、`X-Local-Intent: git-commit`、JSON 与 8 KiB 请求上限；请求对象字段、类型、数组长度和字符串长度严格白名单，超项拒绝。P1 `project-onboarding` 和 P2 `material-linking` 意图及响应保持原义，不放宽 CORS、不允许任意 URL 或 GET 触发 Git 写。错误沿用 `{error:{code,message}}`，候选/预览/确认/结果以稳定 HTTP 与操作状态区分未执行、已完成、部分完成、未知、预览过期、仓库忙、配置不支持和身份缺失；不把超时一律包装为普通失败。
3. 确认必须调用 T02 的持久去重/复核，不在路由重新发 `git commit`；重复相同操作 ID 返回同一已记录结果或待核查状态。无项目 404，已定义路径错方法 405，未知子路由 404。响应不回显完整路径、环境、凭据、原始 stderr 或文件正文。结果中给可点击/可重读的当前真实状态标识，不把旧的 source/history 缓存当成功证明。
4. 测试全部使用临时项目配置与临时 Git 仓库。确认 API 能写的只有该临时仓库和注入的本地操作目录；不访问真实业务目录或远端。

## 验收与停止条件

覆盖错误 Host/Origin/意图/媒体类型/超 8 KiB/多余字段在查项目和写 Git 前拒绝，合法候选/预览/确认/结果读取，重复确认、失效票据、项目切换、项目配置被替换、子进程失败/超时、重启读结果。核对未选暂存与文件保护、P1/P2 路由仍可用、`preview.mjs` 指纹不变。运行 `node --check`、相关 API 测试及必要全量回归。若需放松安全边界、调整 T02 状态语义或允许任意路径，停止并交阶段主控裁决。停写回报变更清单、前后 SHA-256、命令结果、未验证项和 `git status --short --branch`；T03 PASS 后方可交 T04。
