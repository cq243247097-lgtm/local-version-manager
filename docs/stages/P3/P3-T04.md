# P3-T04 任务卡：PC 真实模式提交闭环

本卡仅在 P3-T01/T02/T03 经阶段主控 **PASS** 后交 Gemini；型号由用户选择。阶段主控逐卡审核，总控在阶段交接后独立验收。先核对 T03 的 API 与当前文件指纹。目标是让新手在现有 PC 工作台主动选择文件、审查真实预览、确认本地提交并看到可核实结果；不改变 preview 的模拟提交、不增手机适配或其他 Git 操作。

## 文件所有权

独占 `frontend/app.js`、必要的 `frontend/index.html`/`frontend/styles.css`、`README.md`，以及直接对应的 `tests/frontend_delivery.test.js`、新建 `tests/e2e_git_commit.test.js`（如需要）。不改 `server/*`、`preview.mjs`、材料记录/扫描、P1/P2/总控文档或真实业务仓库。发现 API 契约不足，停受影响 UI 并交阶段主控安排 T03 返修，不私改服务器。

## 用户行为与显示

1. 真实模式的当前项目“源码工作台”增加明确的“选择文件并本地提交”入口。列出服务端候选，按文件勾选，重命名旧/新路径同一选择；显示删除/新增、暂存/未暂存、不能选择的原因。默认不全选，选择至少一个文件，单行提交说明校验。PC 现有布局、材料两个页和已有本地刷新不变。真实项目切换或旧请求晚回时，清空旧票据/选择并按项目 ID 隔离响应。
2. 点击预览只调用服务端预览，显示**服务器核实**的项目、当前分支、选中文件及实际提交范围/有限差异摘要、未选暂存工作会保留、签名/hooks 等不支持原因。确认按钮在预览完成后才出现；显示这是本地提交，**不会推送或联网**。取消关闭不写 Git。确认中禁用重复点击，但以 API 操作 ID 为真正去重依据。
3. `PREVIEW_STALE` 后清除确认能力并提示重新选择/预览；失败/超时/断线后先用相同操作 ID 查询结果，不自动发新的确认。`partial` 明确指出已发生的精确暂存或其他已证实变化；`unknown` 明确提示需要核对，不显示“失败可重试”。只有 API 核实 `completed` 才显示提交 OID/分支和成功。操作结束后刷新真实 source/history；刷新失败保留已核实操作结果及重试入口，不回退演示数据。
4. README 将 `npm start` 从“100% 只读/不联网”改为准确的“查看默认只读、本人确认可本地提交；本批无远端操作”，保留材料目录只读与 `npm run preview` 独立模拟行为。文案尽量用“已暂存/未暂存”等必要概念，并给用户可理解解释，不在日常流程暴露 Git 内部锁/索引实现。

## PC 验收与停止条件

真实 Chromium 1440×900 在**临时 Git 仓库**验证正常提交、取消、重复点击、未选已暂存保持、冲突/无身份/签名/hooks 阻止、预览后变化、结果未知/重启恢复、项目切换、请求失败重试。前后比较 Git HEAD、索引与未选文件；预览/取消必须零写。验证 P1 只读状态与历史、P2 两材料页和关联向导、`npm run preview` 模拟提交仍仅内存操作。运行变更 JS `node --check`、相关测试与同版本必要回归，保存可复核浏览器结果/截图于 `.local/p3-review/`，不要声称未测平台已通过。若 UI 需要改服务器语义、真实仓库写入或远端访问，停止并报阶段主控。

停写交付全部变化文件和前后 SHA-256、浏览器/测试证据、未验证项、`git status --short --branch`。本卡通过后阶段主控仍须集成验收和最终交总控；Gemini 不自行宣布 P3 大阶段 PASS。
