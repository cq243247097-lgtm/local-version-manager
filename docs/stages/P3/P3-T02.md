# P3-T02 任务卡：确认执行、去重与真实结果恢复

P3-T01 功能验收已通过；用户授权保留工具仓库事故现场并恢复 T02。Gemini 型号由用户选择。阶段主控审核本卡，总控只在整阶段交接后独立验收。开始时核对 [T01 复审](P3-T01_R01_REVIEW.md) 与接收 SHA-256：`server/git/commit-preview.js` 为 `b21c2774acbedc0ec61f9b4af807528886f2843e6cce43bdeec6a0d371be2c41`，`tests/git_commit_preview.test.js` 为 `f5e2cca4467745353be7645a5f9392c44deed41a57b8fe01dd5b084832940ebb`。工具仓库本地 `0301a02` 事故提交及 Git 配置保持现场，不能当作测试目标或交付提交；Git 写入测试仅在系统临时仓库。本卡不实现 HTTP、页面、推送、fetch 或分支操作。

## 目标与文件所有权

把 T01 的票据确认变成一次可核对的本地提交，保护未选文件/已有暂存，重复请求和重启后不重复执行。顺序接手 `server/git/commit-preview.js` 及其必要辅助模块；可新建 `server/git/commit-write.js`、`server/git/commit-operations.js` 和 `tests/git_commit_write.test.js`。仅在 T01 已通过的测试中补直接相关用例。不得修改 `server/git/exec.js`、`status.js`、`inspect.js`、`server/app.js`、`config.js`、`security.js`、`frontend/*`、`preview.mjs`、P1/P2/总控文档、真实业务仓库或材料目录。需共享入口改动先报告阶段主控。

## 必须交付的行为

1. 确认只接受 T01 的未过期票据与操作 ID。先以登记项目定位仓库，重查根/common-dir、HEAD、分支、索引、选中文件内容/类型与支持配置；任一相关变化返回 `PREVIEW_STALE`，**零写入**。不接受调用者新传路径、Git 参数、提交说明或 remote。空提交、分离/未出生 HEAD、冲突、正在进行的合并/挑拣/变基仍拒绝。
2. 固定 Git 子命令，专用 `spawn` 写执行器使用 `shell:false`、清理危险继承 `GIT_*`、非交互、受控 stdin、字面 NUL 路径、限时/限输出/子进程退出处理。不要简单把只读 `runGit` 改名后用于写调用，不使用 `add -A`、`commit -a`、`reset`、`restore`、`stash`、`clean`、`--no-verify` 或静默关闭签名。按 T01 探针证实的方案处理未跟踪选中路径；如必须先精确 `add`，只暂存已选精确路径，失败后保留这一步的实际状态并报 `partial`。签名、hooks、fsmonitor、filter 不支持时拒绝而非启动外部程序；身份从 Git 有效配置取得，不自动设置。不得执行任何凭据助手/远端命令。
3. 同一规范化仓库/工作树本工具内部只能有一个写操作，跨标签、跨进程请求也须有界互斥。锁状态、过期和崩溃恢复必须有明确定义；不得误删活动锁。外部 Git 不受该锁控制，执行前后的真实状态必须复查。预览后 HEAD、索引或选中内容变化不盲写；极短竞态不能宣称已被系统级锁消灭。最终提交树和所选内容与预览不符时，不返回普通成功。
4. 第一个可能写仓库的命令之前，将操作 ID、项目/仓库身份摘要、前 HEAD、预期树、票据摘要、阶段写入本工具本地持久记录并 `fsync`/原子落盘。记录目录应以调用者配置所在本地数据目录为边界，测试可注入临时目录；不在被管理仓库写本工具日志。执行后的结果记录 `not_started` / `completed` / `partial` / `unknown`，附真实前后 HEAD、提交 OID（若可证实）、索引变化类别和对用户可理解的恢复提示。持久记录不得包含凭据、文件正文或未脱敏 stderr。
5. 同一操作 ID 在进程内、重启后只能查询已有结果，不再触发第二次提交。命令超时、连接断开、异常退出或状态写回失败时，先查磁盘 HEAD/目标提交/索引及操作记录；能证明完成则给 `completed`，能证明只暂存则 `partial`，无法证明则 `unknown` 并阻止自动重试。新票据也不能用来无提示掩盖同一未确认操作；应明确要求用户先核对。不能以退出码 0 单独宣称成功，也不能因 HTTP 超时把已完成提交当作未执行。
6. 记录和锁仅在本工具本地数据范围内创建，数量/保留期有界；旧操作可查，不因进程重启假装从未执行。不能为了清理异常执行隐式 reset/删除 Git 文件。失败错误码稳定，信息不泄露绝对路径、敏感环境变量或 Git stderr 原文。

## 验证与停止条件

只在系统临时仓库运行，覆盖正常/取消/双击/两个服务实例并发、未选已暂存、选中暂存与未暂存并存拒绝、未跟踪/删除/重命名、特殊路径、冲突、无身份/签名/hooks、预览后外部改文件/HEAD/索引、子进程非零/超时/超输出、精确 add 后 commit 失败、服务重启、结果记录写失败及不可判明结果。每案比较 HEAD、提交树、完整索引和未选文件字节，确认没有意外写入或隐藏丢改动。故障注入须有限，不能无界轮询。执行 `node --check`、定向测试和必要 P1/P2 回归；若未选已暂存无法保护、结果不明仍会自动重试、或需要改 HTTP/前端/架构契约，停止并向阶段主控报告。

停写交付全部变更文件及前后 SHA-256、同版本测试命令/结果、临时夹具状态证据、未覆盖平台与实际 Git 版本、`git status --short --branch`。T02 PASS 后才能交 T03；本卡不触碰真实业务或工具仓库的 Git 状态。
