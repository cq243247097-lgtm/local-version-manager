## 1. 冻结范围与授权

用户本会话选择首批**只做选择文件并本地提交的完整闭环**。本批不实现推送、fetch、创建/切换分支；这些是后续候选，不能借“P3”自行解锁。也不实现 pull、merge、rebase、reset、clean、stash、amend、空提交、强推、执行材料包、自动任务。普通“刷新本地状态”继续不联网。

可以修改本工具代码，并在系统临时 Git 仓库及本地 bare remote 中做验证；不能对真实业务仓库、工具仓库、真实远端执行提交或其他写操作。即使页面能力已实现，也不表示用户授权了某个真实仓库的实际提交。Gemini 由用户自行选择型号、单卡转交并实施；本阶段主控逐卡审查，阶段结束后总控独立验收。任何单卡 PASS 都不是总控 PASS。

只做 PC，保留当前外观、P1 只读工作台、P2 材料管理和独立 `npm run preview` 演示。`README.md` 现称真实模式完全只读，T04 完成时须按实际能力准确更新；此前不提前宣称已支持提交。

## 3. 本地提交的用户语义

用户在当前已登记项目逐个**文件条目**选择；不支持“全部默认勾选”、目录选择、任意路径、hunk 选择或自动扫描后替用户提交。页面显示项目、当前分支、选中的路径与操作类别、已有暂存/未暂存区别、未选文件数、提交说明及预览的实际提交内容摘要；内容预览应给有界变更概览，超限须明确，不能只用工作区总数冒充提交范围。路径在服务端来自 Git 枚举的精确条目，用户只回传短期票据/条目 ID；选中重命名时旧/新路径作为同一个原子条目处理。删除显示删除，未跟踪显示新增；中文、空格和特殊字符按 NUL 分隔及字面路径处理。

提交针对**选中路径当前工作树内容**。选择一个已有暂存路径且工作树内容与暂存一致时，提交该版本；未选中路径已暂存内容仍保留，不混入本次提交。选中路径同时存在暂存和未暂存不同内容时**拒绝本次选择**，提示先由用户在 Git 中处理部分暂存；不能悄悄提交工作树全量、覆盖原部分暂存。任何未解决冲突、正在合并/挑拣/变基、子模块或稀疏检出等无法证明安全语义的状态，首版保守拒绝整个提交，并给具体原因。忽略文件、特殊类型、无法稳定读取的文件不可选。分离 HEAD 和未出生 HEAD 本批明确拒绝；不自动建分支或创建首次提交。只接受已有、附着的本地分支。提交说明为非空单行，限制长度和控制字符，拒绝空树、空提交；不调用编辑器。

实际提交优先验证 Git `commit --only` 的按字面路径语义：它使用选中工作树内容、排除其他路径已暂存内容，并由 Git维护主索引。未跟踪文件如果必须先显式 `add`，只暂存精确选中路径，先在临时仓库探针确认行为；该步若成功而提交失败，返回“部分完成：文件已暂存”，不执行 reset/restore 回滚。若此方案不能同时满足选中路径和现有索引保护，**停止改造并由阶段主控重新裁决**，不能退回 `add -A && commit`。Git 官方说明见 [git-commit](https://git-scm.com/docs/git-commit) 的 `--only` 与 NUL 路径参数文档。

## 4. 预览、确认与实际变化

预览由服务端生成不可猜的短期票据，绑定项目 ID、规范化工作树根与 Git common-dir、附着分支 ref、HEAD OID、真实索引的内容指纹、选中路径及旧/新路径、选中工作树内容/类型指纹、预期提交树摘要、提交说明和检查时间。票据只存在本机内存并有有限 TTL；服务重启后旧票据失效。前端不可自行改路径或分支。确认前按同一规则重读配置与仓库身份、HEAD、索引、选中路径和不支持的配置；任何相关变化报 `PREVIEW_STALE`，要求重新预览，不自动改选或继续提交。未选工作区文件变化若不影响提交树可不阻止，但必须确保未选暂存变化不被悄悄纳入；审查时需证明判定条件。

同仓库本工具操作需串行，包括多个浏览器标签与服务实例；锁按规范化 Git common-dir/工作树身份关联，锁必须有界且不能误删活动锁。外部 Git 客户端、编辑器和文件系统不会受本工具锁控制：最后一次检查到 Git 写入之间仍可能有竞态。实现须在执行后比较真实 HEAD/树、索引与所选内容，不符合预期时报告已完成但异常或结果未知，不声称系统级事务。重复点击使用同一操作 ID；前端禁用按钮只是体验，服务端也必须持久阻止重复提交。超时、断线或服务重启后，先读取操作记录与磁盘事实；结果未知时禁止以相同或新票据自动重试。

## 5. Git 写调用与配置策略

新增专用写执行器，固定允许命令和参数结构，使用 `spawn` 且 `shell:false`；不接受任意命令、选项、路径或仓库 URL。清理继承的可改变 Git 目标/配置/索引的 `GIT_*` 环境，固定非交互、无网络、无编辑器；有限超时、输出上限、退出与终止处理。只读 `runGit` 的 `--no-optional-locks`/hooks 设置不可直接复制到写调用。参数使用字面路径和 NUL 文件/标准输入以处理换行、空格、中文和以 `-` 起始的文件名。拒绝不受支持的 `core.fsmonitor` 外部程序、适用路径的外部 clean/filter 程序及无法证明安全的仓库扩展；预览和确认都检查。不得修改仓库、全局或系统 Git 配置。

首版**不支持执行用户 commit hooks、签名程序或凭据助手**。如有效 `core.hooksPath`、任一活动提交 hook、`commit.gpgSign=true` 或其他要求签名的有效配置存在，预览应明确拒绝，并指明请用户用常规 Git 工具完成该次提交；不能为了成功静默加 `--no-verify`/`--no-gpg-sign`。如果采用受控空 hooks 目录封闭检查后新增 hook 的竞态，页面必须明确说明本功能只在“无提交 hook 的仓库”运行，且预览/确认均拒绝已有 hook；不得把该控制冒充运行了用户 hook。身份使用 Git 当前有效 author/committer 配置，缺失时报 `IDENTITY_MISSING`，不自动设置或把身份填进命令行。无远端操作，因此凭据助手不得启动。Git 官方 [hooks](https://git-scm.com/docs/githooks) 文档列出可执行 hook 和 `core.hooksPath` 行为。

## 6. 接口与恢复状态

建议专用 `POST /api/projects/:id/commit/preview`（严格选中条目 ID 与单行说明）和 `POST /api/projects/:id/commit/confirm`（严格票据和操作 ID），另设只读的 `GET /api/projects/:id/commit/operations/:operationId` 查实际结果。可增加只读候选清单接口，但不得让 GET 写 Git、领取票据或启动任何子进程写操作。统一意图 `X-Local-Intent: git-commit`，沿用精确 Host/Origin、8 KiB 上限和无 CORS 放开；确认只凭已登记 ID 定位仓库，不接受路径、命令或 remote。详细字段名由 T01/T03 顺序固化，若要更改此处语义先由阶段主控修订方案。

操作状态至少区分 `not_started`、`completed`、`partial`、`unknown`；另有预览过期、状态冲突、仓库忙、不支持配置、身份缺失和 Git 拒绝等稳定错误码。成功只有在真实 HEAD 的新提交及预期树、索引保护事实核对后才能返回；命令退出码 0 不是唯一证据。开始写入前持久写操作意图；结束后持久记录结果和必要的前后 HEAD/树/索引事实。日志和响应不泄露完整环境、凭据、仓库绝对根、文件正文或未经过滤的 Git stderr。取消预览不写仓库；开始执行后取消/超时需查询实际结果，不自动重试或隐式回滚。记录保存于本工具本地数据目录，具备有限数量/时效和原子落盘规则；既有 P1/P2 配置保存不得受其影响。
