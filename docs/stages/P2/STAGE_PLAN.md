## 3. 关联配置与 HTTP 契约

材料种类只允许 `installer`、`upgrade`。配置可选增量为项目条目中的 `materials: { installer?: { root: string }, upgrade?: { root: string } }`；旧配置未带 `materials` 完全合法，表示未关联。原 `repositoryPath`、项目名、ID、未知键和其他项目原样保留。公用项目列表仍只公开 `{id,name}`，不泄漏材料根；专用状态接口也不返回绝对根。只有用户输入/检查/确认页面显示必要的输入根与规范化根。

| 路由 | 请求/结果 | 限制 |
| --- | --- | --- |
| `POST /api/projects/:id/materials/:kind/inspect` | 严格 `{rootPath}`；返回内存高熵 `inspectionId`、输入与 `realpath` 根差异、目录身份及同一扫描器的有界预览摘要 | 仅已登记项目、两种 kind；路径只能来自此 POST；校验目录存在、可读、绝对路径。票据绑定项目、kind、规范化根、检查时配置关联状态和目录身份，10 分钟过期/重启失效。取消不保存。T01 可先返回浅检查；T02 用正式扫描器补预览。 |
| `POST /api/projects/:id/materials/:kind/confirm` | 严格 `{inspectionId,replaceExisting}`；成功 `200 {association:{projectId,kind,linked:true},alreadyAssociated}` | 不接受路径；必须精确同源及意图头。更换旧根须在检查页明确展示并 `replaceExisting:true`；票据过期/目录身份变化 400 `INSPECTION_STALE`，配置关联在检查后被其他进程改变 409 `MATERIAL_CONFLICT`。相同规范化根幂等且不重复落盘。 |
| `GET /api/projects/:id/materials/:kind` | 未关联 `200 {state:'unlinked'}`；已关联返回完整/部分清单、树、声明和警告 | GET 只凭 ID/kind 从磁盘配置定位根；不接受 path、下载、静态暴露或任意文件接口。根不存在/无权限/不可扫描报明确非 2xx 错误；文件级失败为 `partial` 加条目错误，不能伪装空目录。T02 实现。 |

错误沿用 JSON `{error:{code,message}}`：非法参数 400 `INVALID_INPUT`，未知项目 404 `PROJECT_NOT_FOUND`，未知子路由 404，已定义路径错误方法 405，票据失效 400 `INSPECTION_STALE`，配置忙 409 `CONFIG_BUSY`，关联并发冲突 409 `MATERIAL_CONFLICT`，根失效 409 `MATERIAL_ROOT_UNAVAILABLE`，配置损坏 500 `CONFIG_INVALID`，写失败 500 `CONFIG_SAVE_FAILED`。响应不泄露根、系统内部异常、源文件正文。具体错误边界如需调整，先由阶段控制更改本契约。

确认时使用**同一个** `projects.lock`，持锁重读整个配置、重新校验项目存在与票据绑定的旧关联，复核目录 `realpath` 与身份，保留原配置其他字段，原子替换并清理临时文件/锁。新关联和 P1 项目登记并发时都不可丢写。材料目录绝不写入；检查期间目录变化不能借旧票据直接确认。

## 4. 有界扫描、来源和事实分层

扫描对象仅为已确认根或检查中的主动输入根。根取真实路径；对每个后代 `lstat`，默认不跟随 symlink、junction、reparse point 等链接，链接仅作为“已跳过”条目显示。拒绝声明中的绝对路径、盘符、反斜杠、空/`.`/`..` 分段、越界路径；记录文件不能让扫描器读取根外文件。原始包文件只取 `lstat` 元数据，不读取正文、不下载、不执行。显示相对路径；元数据全视为不可信文本，前端转义。

冻结首版上限：根为深度 0，最多进入深度 5；全局最多 5000 条文件/目录/链接；单个目录流式采集至 1001 条，超过 1000 则**不输出该目录的任意不稳定部分子集**，仅保留目录节点、标记截断且不下探；相对路径最多 1024 字符，记录文本字段最多 512 字符；可选记录 JSON 最大 256 KiB、最多 1000 条记录；单次遍历设 5 秒逻辑截止，异步操作前后检查预算，超时后不发起新 I/O 并返回部分/错误；序列化响应最多 8 MiB，按稳定顺序截断且标明原因。逐目录以原始相对路径的代码点顺序排序；完整结果稳定，限额结果必须含 `truncated:true`、原因、已读计数与未覆盖范围，不能称全量成功。目录读取失败与空目录分开；扫描中消失/属性变化的文件保留相对路径并标 `changed`/`unavailable`，不会为其给出当前文件已核验结论。若操作系统 I/O 本身阻塞超过预算，应作为实际限制记录，不宣称强制可中断。

无记录的文件和空子目录也展示；仅名称、类型、大小、相对路径与“待识别”，不从路径/文件名推断精确版本、修订、平台、源码提交或验证通过。可选、只读、工具可识别的记录约定见 [MATERIAL_RECORD_V1.md](MATERIAL_RECORD_V1.md)。旧材料没有它仍可扫描；实际旧格式由用户授权样本证据决定是否适配。缺失记录、损坏 JSON、重复或互相冲突的声明均不吞掉物理文件，分别显示 `no-record`、`record-invalid`、`record-conflict`；引用缺失文件保留“声明指向的文件缺失”记录，不造出真实文件。

GET 的稳定字段约定：`{projectId,kind,state,scan,tree,items}`；未关联时 `state:'unlinked'`、`scan:null`、空数组。已关联时 `state:'linked'`，`scan` 含 `status:'complete'|'partial'`、`scannedAt`、`truncated`、`reasons[]`、`entriesScanned`；`tree[]` 为按相对路径排序的目录/文件/跳过链接节点，含稳定 `id,parentId,relativePath,name,type`；`items[]` 对应物理材料文件或缺失引用，含稳定 ID、相对路径、`physical`、`declaration`、`integrityRecord`、`installationRecord` 和 `compatibility`。每层分别有 `state`/来源标识，未知值为 `null` 或明确枚举，不借用空字符串/零。`compatibility` 含 `state:'available'|'unknown'|'none'|'invalid'|'not-applicable'`、原始 `directFrom` 与唯一的 `minimumDirectSource`（无可比较最低值时 `null`）。绝对根不在响应中。T02 可以增补非破坏性字段，但改字段名、状态或含义先由阶段控制裁决，T03 不另算最低值。

每项分开呈现：① 本次 `lstat` 文件存在/类型/大小；② 记录声明的版本、修订、平台、来源、兼容；③ **历史完整性记录**的原结论、日期与来源；④ **历史安装/升级验证记录**的环境、日期、结果与来源。P2 不重算包哈希、不实际安装；即使历史记录写“通过”，页面也必须标“记录称通过，当前文件未核验”。记录所存大小/修改时间与当前文件不同或扫描中变化时，显示“属性与记录不一致/需复核”，不武断称内容已变或已验证失败。

## 5. 升级兼容与版本语法

每个**升级包文件/修订**独立拥有直接支持来源列表，树节点与右侧详情使用 API 返回的**同一个** `minimumDirectSource` 计算结果。目标版本标题可按声明分组，但不同包/修订的最低值必须分别可见，不能合并成假版本级最低值。`directFrom` 缺失为 `unknown/待确认`，明确空数组为 `none/未声明任何直接支持来源`，有非连续列表只列原项，不推断中间版本或传递升级路径。记录给出的“支持直接升级”也不是实测；历史验证记录另列。

首版可比较版本仅接受 `v?MAJOR.MINOR.PATCH`，三段十进制非负整数，每段 `0..999999`，除 `0` 外不得有前导零；可选小写 `v`，比较时规范化为三元整数。`v1.2`、`V1.2.3`、预发布 `v1.2.3-rc.1`、构建标识 `+build`、版本范围、通配符和超上限数字均**不可比较**，原文仍展示。任何 `directFrom` 元素非法、不可比较、重复规范化后矛盾，或不早于目标版本时，不从剩余项局部计算貌似完整的最低值，整份兼容声明标 `invalid/需核对`。目标版本本身不可比较同样无最低值。版本数字不使用演示页字符串排序。合法列表按数值三元比较取最小，重复完全相同版本可去重并保留原声明列表。

## 6. 真实 PC 页与恢复

真实模式在现有“安装包资料库”“升级包资料库”的树形和详情容器内显示专用 `GET` 数据。无关联、关联根为空、空子目录、仅未知文件、部分扫描、记录损坏/冲突、根失效均有各自可理解状态；不得在真实模式回退演示数组或把演示标签混作该项目材料。关联向导显示绝对输入根和规范化根供本人确认，更换关联特别提示；取消/失败不写配置。材料项在树上显示版本与修订来源；升级包折叠后仍可看见**该包/修订**最低直接支持来源或“待确认/无直接来源/需核对”。右侧保留来源列表、事实分层与记录来源。原 PC 视觉和独立 preview 演示行为保持。

真实模式请求状态按 `projectId + kind` 隔离：切项目、切材料页、刷新或重试时使用序号/取消旧结果，不显示上一个项目的材料；列表错误重试列表、关联错误重试检查/确认、扫描错误重试当前项目当前 kind。断线后保留选择与真实模式，恢复时重发对应请求。API 的截断、警告和扫描时间要原样传达；界面不能把 `partial` 写成“已全部扫描”。
