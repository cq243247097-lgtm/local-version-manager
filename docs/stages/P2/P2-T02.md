# P2-T02 任务卡：有界只读扫描、记录来源与升级兼容

**P2-T01 已获阶段控制 PASS**，由用户单独交 Gemini。接收 [T01 返修验收及实际指纹](P2-T01_REWORK_ACCEPTANCE.md)，阅读 [阶段方案](STAGE_PLAN.md) 第 3–5、7 节和 [可选记录 v1](MATERIAL_RECORD_V1.md)。本卡实现已关联材料的安全 GET 清单，并把同一扫描器的预览摘要接入 T01 检查流程。用户尚未给出真实旧格式时，只用系统临时目录及可选样例验证；不能称旧归档适配完成。

## 写入权与边界

T01 停写/PASS 后顺序接手 `server/app.js`；允许新建 `server/materials/scan.js`、`records.js`、`versions.js` 和必要小模块，以及 `tests/materials_scan.test.js`、`tests/materials_records.test.js`、`tests/materials_api.test.js`。若 T01 选用不同模块名，先核对交付接口再做等价最小实现。默认不改 `server/config.js`、`server/security.js`、`server/materials/association.js`；确需改共享接口，先说明具体调用点与最小范围，经阶段控制确认文件所有权后顺序修改。不得改 `frontend/`、`server/git/*`、`preview.mjs`、P1 文档/基线、总控文档、真实材料或业务仓库。

## 交付契约

1. **GET 仅凭登记关联**：`GET /api/projects/:id/materials/:kind` 只接受合法已登记项目 ID 与 `installer|upgrade`，从当前磁盘配置定位关联根；未知项目 404，未关联为 `200 state:'unlinked'`。请求的 query/path/body 不能提供文件系统路径或下载目标。根失踪、变链接/越界或不可读返回 `MATERIAL_ROOT_UNAVAILABLE` 等非 2xx；不返回绝对根/栈/包正文。保持 P1 路由 404/405 精确行为。检查接口的预览和 GET 调用同一扫描器，不维护第二套状态/版本计算。
2. **有界目录扫描**：根 `realpath` 不得变更为当前关联之外；遍历每个后代先 `lstat`，跳过 symlink、junction/reparse point，绝不沿链接进入根外或读取其目标。文件只读元数据，不打开包内容。深度 5、全局 5000 项、单目录最多 1000 项、相对路径 1024 字符、单记录文本 512 字符、序列化响应目标 8 MiB、5 秒检查预算；超限返回 `partial`、`truncated:true`、原因/已扫描数，不显示“空/完整”。单目录超过上限时不输出随机前 1000 个子项，避免不稳定半清单。逐目录路径排序，合法完整扫描稳定；空根与含空子目录要区分。文件/目录在扫描中消失、无权限或属性变化分别标清，保留已安全读取结果，不能吞错成空目录。根级不可访问为接口错误，子项失败为 `partial`。测试在 Windows 能创建的链接类别中实际验证，不凭推测声明其它平台。
3. **事实与来源**：所有可见文件/空目录先有物理清单；未知文件标待识别，不从文件名或目录名补版本/源码/验证。仅解析根级普通文件 `material-records.json`，限制 256 KiB/1000 条、UTF-8 JSON，按 [v1 契约](MATERIAL_RECORD_V1.md) 验证。声明 `file` 必须是安全根内相对路径，不能通过 `..`、绝对/盘符、反斜杠或链接读取外部；实际包文件不读正文。记录缺失、损坏、重复冲突、指向缺失文件、记录与当前大小/mtime 不一致均用不同状态/警告表达，且不隐藏物理文件。历史完整性与安装/升级验证记录在 API 中保留其来源、时间、环境及“记录称”语义；本阶段不计算哈希、不执行安装/升级，不能把文件存在当成验证通过。
4. **版本与兼容**：仅 `v?MAJOR.MINOR.PATCH`，三段 `0..999999` 且无非法前导零可比较；预发布、构建标识、范围、通配符、缺补丁与非法大数保留原文，标不可比较。升级每个物理包/修订有独立 `directFrom`；缺字段 = `unknown`，空数组 = `none`，合法非连续列表只表达列举点。任何元素非法/不早于目标或目标非法时整份列表 `invalid`，`minimumDirectSource:null`，不能只取合法子集。合法列表以数字三元组取最低，摘要与详情由同一 API `compatibility` 对象产生；不同修订不能归并最低值。可复用已有演示布局，**不能复用演示字符串 `localeCompare` 作为真实版本规则**。
5. **稳定数据契约**：返回 [阶段方案第 4 节](STAGE_PLAN.md) 的 `projectId,kind,state,scan,tree,items` 结构；`scan.status` 的 `complete|partial` 与 `truncated/reasons` 准确，稳定 item ID 根据 kind+相对路径确定，不含绝对根。`physical`、`declaration`、`integrityRecord`、`installationRecord`、`compatibility` 分层，未知/无记录不填假值。`items[]` 中同目标版本不同修订保持为不同 ID 和独立声明。元数据仅作数据传输，长度/数量有界，前端后续按文本转义。任何增补字段在交付中说明；改变已冻结语义先报阶段控制。

## 定向验证与交付

临时夹具覆盖安装/升级两个根、未关联、空根/空子目录、未知文件、普通 v1 记录、损坏/超大/不支持版本/重复/缺失引用、不同修订冲突、记录属性不符、空 `directFrom`/缺字段/非连续列表/非法元素/预发布/范围、根与子项消失/无权限、链接越界、深度/目录/总量/时间上限。验证排序、截断、详情与最低摘要同源，以及检查预览/GET 一致。扫描前后材料文件、记录文件和 Git 仓库的字节/存在状态一致；不得执行包内容。API 安全验证任意 path 参数、越界引用、未知项目/kind、非法方法、错误隐私。跑相关定向测试和 `npm test`，变更 JS 各自 `node --check`，必要 P1 回归只读检查。

停写后回报本卡文件前后 SHA-256、测试命令与实际计数、扫描限额/平台实测证据、未支持的旧材料格式及权限限制、是否访问真实项目、`git status --short --branch`。未得到用户授权目录时，报告“通用扫描与 v1 样例通过，真实旧格式未对照”，不可自称 P2 最终 PASS。不得提交推送或自动联系下一卡；若真实样本要求别的格式，先由阶段控制记录证据并决定定向适配范围。
