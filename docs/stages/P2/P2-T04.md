## 只读字段契约

保持已有 `schemaVersion:1` 和现有记录向后兼容，只增加必要的可选白名单字段：

1. `releaseStatus` 只接受 `candidate|released`，旧三包均为 `candidate`；候选不等于可用或已安装验收。未声明则为未知。API 和两区详情显示中文状态，不借颜色暗示本次验证通过。
2. `targetVersion`、`revision` 可明确为 `null` 表示记录未提供，保留非法非空字符串的原校验；不能为了使记录合法而从文件名猜值。若版本或修订未知，条目仍可关联已知包并显示“未声明”。
3. `recordedFile` 支持仅登记 `sizeBytes` 与可选的 `mtimeMs`、`sha256`：大小可与本次 `lstat` 比较，未登记时间不比较；`sha256` 仅是**历史登记摘要**，P2 不重算当前文件，也不因此产生 `integrityRecord.result:'passed'`。大小相等只表示属性相符。值须严格校验、长度有界、只按文本显示。
4. 可选 `evidenceSource` 为根内安全相对路径文本，供显示旧事实来源（例如 `install-v0.2.6-r2-fix1/release-record.json`）；验证语法与长度，不凭字段去读取任意文件。API 仍只输出白名单字段和相对路径，不输出原始 JSON 或绝对根。
5. 未有独立安装/升级测试证据时，`installationRecord` 保持无记录/未验收。升级包 `directFrom` 缺失或为 `null` 即 `unknown`、`minimumDirectSource:null`；绝不写 `[]` 或从 rc9→c4 文字推出最低版本。现有 v1 的有效直接来源计算和错误规则保持不变。

字段名/取值若需在实现中调整，先记录等价契约并由阶段控制裁决，不改变上述事实语义。前端移除写死“声明仅来自 material-records.json”的说明；同时显示统一记录与可选证据来源。
