## 页面行为

1. **真实/演示严格分离**：`npm start` 注入 real 标记后，安装包和升级包页只取当前已登记项目对应 kind 的 GET 数据。两区不能再把 `installers`/`upgrades` 演示数组显示成当前项目材料，真实空态不能落回虚构卡片。`npm run preview` 仍由原标记走现有演示数组、演示交互与外观，不读本地项目/材料，不新增包执行或下载按钮。保持现有桌面导航、树形左栏、右侧详情和总体视觉；仅必要样式变化，不做手机端。
2. **关联向导**：未关联页提供“关联安装包目录/升级包目录”；用户输入本机绝对根，调用专用 inspect。检查页醒目展示输入根、规范化真实根、同一扫描器给出的完整/部分预览及错误/截断，明确“仅确认后写本工具配置，材料目录只读”。已有根更换须显示原关联状态和明确确认，不自动覆盖。取消、检查失败、票据失效/目录变化、配置忙/冲突/保存失败都有可理解提示和重试路径；确认 POST 不带原始路径。成功后读取当前 kind 清单，并保持原项目选择。
3. **两区树与详情**：真实空根为“目录已关联但暂无材料”，空子目录仍可见；未知文件列名称、类型、大小、相对路径与待识别，不猜版本/平台/源码/验证。记录有效时按声明显示目标版本、修订、文件与来源，重复/缺失/损坏记录显著提示且保留物理文件。安装包详情严格分开“本次看到文件”“记录所述完整性”“记录所述安装验证”，历史 passed 必须写“记录称通过，本次未核验当前文件”并附来源/环境/时间。记录属性与当前不一致显示需复核，不显示绿色“可用”。升级包详情逐项列 `directFrom`；左树**每份包/修订**折叠后仍显示 API 给的 `minimumDirectSource` 或“待确认/未声明直接来源/需核对”，不同修订不合并。不得前端重新计算最低值或用演示排序；兼容声明不是实测和中间路径。
4. **切换与恢复**：按 `projectId + kind` 管理当前请求与选中 item，切项目/材料页、并发刷新、重试、检查确认后旧响应不得覆盖新页面或混入另一个项目。失联时保留真实模式、项目/kind 和输入；列表/扫描/关联错误各重试其来源，请求恢复后解除错误。根失效显示“重新关联/重试”，`partial` 和 `truncated` 始终可见，绝不写“扫描完整”。项目选择器、P1 源码区刷新/重试与真实 Git 图不因本卡退化。
5. **安全展示**：只在用户主动检查/确认界面显示必要绝对根；普通树/详情不显示根、文件正文、下载 URL 或远端凭据。相对路径、记录说明、版本等所有磁盘来源字符串按文本转义；CSP 仍同源，无外部 CDN。完整性与安装状态不借颜色/图标暗示本次已验证。`README.md` 写明双入口、材料关联和旧目录无记录时的待识别状态、只读及版本限制；`docs/P2_DELIVERY.md` 只记录实际版本、证据、指纹和未验证项，不宣称旧格式已适配。
