# P2-T01 任务卡：材料目录关联检查与配置保存

将**本卡单独**交给 Gemini 实施。目标是给已登记项目的安装包/升级包根建立“主动输入 → 只读检查 → 本人确认 → 仅保存工具配置”的安全骨架；暂不做递归扫描、记录解析和材料页面。本卡可完全使用系统临时目录，不等待真实材料路径。开始前阅读 [阶段方案](STAGE_PLAN.md) 第 1–3、7 节、[总控交接](../../P2_STAGE_CONTROL.md)、P1 最终 PASS；报告工作目录、`git status --short --branch`、适用 `AGENTS.md` 与接收指纹。

## 写入权与接收基线

唯一允许写入：`server/config.js`、`server/security.js`、`server/app.js`，新建必要的 `server/materials/association.js`，以及直接验证本卡的 `tests/materials_association.test.js`、`tests/config.test.js`、`tests/security.test.js`、`tests/api.test.js` 的必要部分。此卡独占这些共享文件，停写并经阶段控制 PASS 后才移交 T02。禁止改 `server/git/*`、`server/static.js`、`frontend/*`、`preview.mjs`、`package.json`、`.local/baselines/P1/`、P1/总控文档或真实业务/材料目录。

## 必须交付的行为

1. **P1 配置兼容**：旧 `{id,name,repositoryPath}` 项目配置仍能读取。可选 `materials.installer.root`、`materials.upgrade.root` 为规范化绝对真实目录；无字段即未关联。修改 parser 时保留 P1 `GET /api/projects` 的 `{id,name}` 脱敏语义、已有项目 Git 读取和确认登记；配置中未知原始键与其他项目原样保留，不静默删掉。损坏或不合规范的新字段返回 `CONFIG_INVALID`，旧文件字节不变。
2. **专用检查**：`POST /api/projects/:id/materials/:kind/inspect` 仅接收 `{rootPath}`，`kind` 精确为 `installer|upgrade`，ID 沿用 P1 合法格式且须已登记。先执行唯一 Host、同源 Origin、非 cross-site、JSON/8 KiB 等前置安全校验，意图头为 `X-Local-Intent: material-linking`；P1 接口继续要求原 `project-onboarding`。拒绝多余字段、相对路径、URL、不可达/非目录路径。只对用户明确输入的目录执行 `lstat`/`realpath` 等浅检查，不遍历其他位置，不执行目录内容。返回高熵内存 `inspectionId`、输入与规范化根的可核对信息、是否已有旧关联；根经过 symlink/junction 时显示最终真实根供本人确认。票据绑定项目、kind、根身份和检查时旧关联，TTL 10 分钟且重启失效。T02 会顺序加上同一扫描器的预览摘要，本卡不伪造“记录已识别”。
3. **确认保存**：`POST /api/projects/:id/materials/:kind/confirm` 请求严格为 `{inspectionId,replaceExisting}`，**不接受路径**。检查前无保存；旧根更换必须预览告知并显式 `replaceExisting:true`，否则 409 `MATERIAL_CONFLICT`。确认时复核票据/项目/种类/真实目录身份；过期或目录被替换报 400 `INSPECTION_STALE`。两次确认同一根幂等返回 `alreadyAssociated:true`，不重复写入；若其他实例在检查后改了该关联，拒绝 409，而非凭旧票据覆盖。
4. **同一配置锁**：沿用 `server/config.js` 的 `projects.lock`、持锁重读、原子临时文件+`fsync`+`rename`、异常清理。材料确认与 P1 新项目登记并发均不能丢失项目、Git 路径、另一种材料根或未知配置键。文件被外部删除/篡改时不能凭内存票据假成功。保存失败保留旧字节、临时文件和锁不遗留。仅 `.local/projects.json` 或测试隔离配置可写；材料目录、被管理仓库、全局配置不写。
5. **路由和返回**：成功检查只在该主动流程返回必要绝对路径；成功确认只返回 `{association:{projectId,kind,linked:true},alreadyAssociated}`，不回显根。错误采用阶段方案第 3 节的状态码与代码；未知路径 404，已定义路径错误方法 405。T02 的 GET 暂不实现，不对任意 `/api/projects/*` 模糊返回 501；不增加文件下载/静态路径。

## 定向验证

用临时项目配置、临时 Git 仓库和临时材料目录验证：未关联/两个 kind 分别关联、旧配置读取、取消/检查失败零写入、子目录输入是否只按用户选择根保存（**不自动上提到任意父目录**）、真实路径规范化提示、重复/并发确认、新项目登记与材料确认交错、不同根冲突、替换显式确认、票据过期/重启/目录更换、配置损坏及保存故障旧字节保留。对材料目录和被管理仓库检查前后做内容/存在状态快照。POST 安全测试覆盖错误 Host/Origin/意图/Content-Type、超 8 KiB、额外路径/命令字段，证明在读配置/票据前拒绝。跑受影响测试和 `npm test`，变更 JS 分别 `node --check`。只复测必要 P1 回归，保留 `preview.mjs` 指纹。

停写后向用户回报全部新增/修改/删除文件及前后 SHA-256、实际命令与结果、夹具证据、P1 兼容结果、未验证项、是否碰真实业务项目、`git status --short --branch`。不联系下一卡、不自行宣布 P2 完成；需扩大写入、扫描真实目录、改安全/配置契约或发生不可解释的保存风险时停止受影响部分报阶段控制。
