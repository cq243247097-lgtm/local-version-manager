# P1-T02：Git 状态、历史与接入检查

将本卡单独交给用户选择的 Gemini 实施。仅当 P1-T01 由阶段控制记录 PASS、且用户带来同一版本的 T01 交付指纹后才可执行。P1 阶段控制验收本卡与阶段集成，总控验收大阶段。

## 目标、前置和文件所有权

目标：实现共享 Git 只读读取，完成已登记项目的 `GET /api/projects/:id/source`、`/history`，以及专用的 `POST /api/projects/inspect` 检查。接入检查复用同一状态/历史读取，不另造一套计数；本卡不保存项目配置、不改 PC 页面、不接材料、不加 Git 写操作或联网操作。

开始时核对 T01 PASS 记录、实际文件指纹、`git status --short --branch`、适用 `AGENTS.md` 和 `.local/baselines/P1/manifest.json`；发现意外变化停止覆盖。阅读 `docs/stages/P1/STAGE_PLAN.md` 第 3–9 节及本卡。允许写 `server/git/`、顺序修改 T01 的 `server/` HTTP 入口和必要的接入检查模块、`tests/` 中 Git 解析/临时仓库/API 测试。不得写 `frontend/`、`preview.mjs`、`package.json`、根 README、总控文档或本目录阶段文件。复用 T01 的错误体/Host/Origin/POST 校验，不另建一套服务器。不得覆盖 T01 基线原件。

## Source API 的冻结契约

`GET /api/projects/:id/source` 返回 `{ scannedAt, branch, headState, changes, changedCount, upstream }`，`scannedAt` 是 ISO 8601 UTC 的本地扫描完成时间。`headState` 仅 `attached|detached|unborn`；分离 HEAD 的 `branch:null`，未出生分支仍保留其名称。空仓库可有未跟踪文件，不能把状态错误当作零文件。

状态由 Git porcelain v2、`-z` NUL 输出与 `--untracked-files=all` 读取，显式识别重命名。解析 `1`、`2`、`u`、`?`，忽略 `!`；每项至少 `{ path, oldPath, indexStatus, worktreeStatus, conflicted }`。普通项 `oldPath:null`，重命名双路径在同一项；未跟踪状态 `?/?`；无变化一侧用 `.`。保留冲突状态，不藏在普通修改里。同一路径既暂存又未暂存只计一次，`changedCount===changes.length`，不是 porcelain 文本行数也不是 25 的上限。对 `path` 再对 `oldPath` 按 UTF-8 字节排序。文件名始终当文本，不进入 HTML/命令拼接。

`upstream` 为 `{ state, name, ahead, behind }`。仅已配置且可读、差异计算成功时 `state:"available"`，数量是非负整数；缺上游（包括 detached/unborn）为 `not-configured`、`name:null`、两数量 `null`；已设置但跟踪引用缺失/不可比较为 `unavailable`、数量 `null`，可保留安全引用名。支持本地上游和本地保存的远端跟踪引用。读取不 fetch，不能把扫描时刻当远端获取时刻。

## History API 的冻结契约

`GET /api/projects/:id/history` 返回 `{ scannedAt, commits, refs, truncated }`。每条 commit 含 `{ oid, parents, subject, committedAt }`，最多 100 条；父 OID 保持真实完整，即使父提交未出现在返回窗口。引用 `{ name, oid, kind }`，kind 仅 `local-branch|remote-tracking|tag|head`；附注标签剥离到所指提交，HEAD 与具名引用可以同时存在。只遍历 HEAD、`refs/heads/`、本地 `refs/remotes/`、`refs/tags/` 可达的提交，不把 stash/notes/reflog/网络对象并入。所有引用名及远端跟踪引用只是本机数据，不表达远端实时状态。

固定引用集合顺序，以 Git 拓扑顺序和提交时间进行稳定的历史排序；同一未变化仓库重复请求应同序。查询第 101 条只判定 `truncated`，返回前 100 条；不能按各分支先截断再合并。空仓库返回空 commits 且 `truncated:false`。保留超出窗口的父 OID 和未显示提交的 refs，供 T04 区分窗口外边界，绝不可替换为窗口内其他行。`truncated:true` 代表可达历史超过本窗口。

## 接入只读检查契约

`POST /api/projects/inspect` 是 P1 唯一允许未登记路径的接口。仅接收 `{repositoryPath}`，UTF-8 不超过 4096 字节、请求体总计不超过 8 KiB；必须先通过 T01 的精确 Host、同源 Origin、JSON Content-Type、`X-Local-Intent: project-onboarding` 与 Fetch 元数据检查。拒绝相对路径、URL、文件、未知命令字段及非目录；不得列盘、读文件内容或执行客户端提供的命令。仅检查用户给的当前主机绝对目录，输入仓库子目录时用 Git 工作树根与 `realpath` 规范化；非 bare Git 工作树可接入，bare/非 Git 提示本阶段不支持。附注：仓库中未跟踪和未提交内容无需先提交。

响应 `{ inspectionId, repositoryRoot, headState, branch, latestCommit, changedCount, upstream, hasHistory, scannedAt }`。`repositoryRoot` 是仅在此本机检查结果展示给当前用户核对的规范化绝对根路径，不写普通项目列表/日志；`latestCommit` 为 `{oid,subject,committedAt}` 或 `null`，`hasHistory` 仅在 HEAD 有提交时为 true。其余状态与 source API 同义，远端跟踪仅本地快照。空仓库允许成功检查，未跟踪文件如实计数。成功检查时生成高熵不可猜测的 `inspectionId`，服务进程内最多保留 32 项、最长 10 分钟，保存规范化根、绝对 git-dir realpath 和摘要供 T03 确认；失败/取消绝不写配置。T03 负责确认时重新检查身份与票据生命周期；本卡只提供可复用的检查能力与票据查找接口。不能把本次只读检查当作登记完成。

## 命令和错误边界

仅使用已安装 Git CLI，以参数数组、`shell:false`、指定工作目录执行。禁止交互提示、可选锁、外部 diff/textconv、hooks、shell；Windows 不弹子进程窗口。每命令有限超时和输出字节上限，超限是显式 `GIT_TIMEOUT`/`GIT_OUTPUT_LIMIT` 非 2xx，不能截断后报成功。不得修改工作区、索引、引用、Git 配置，也不设置全局 `safe.directory=*`。遇到所有权检查提示 `GIT_UNSAFE_DIRECTORY`。缺 Git、非仓库、路径不存在/非目录、其他读取失败分别报 `GIT_UNAVAILABLE`、`NOT_REPOSITORY`、`PATH_UNAVAILABLE`、`GIT_READ_FAILED` 等明确码和中文说明；除 inspect 的 `repositoryRoot` 外，不回显绝对路径、OS 堆栈、远端 URL/凭据。非法/未知项目 ID 返回 404，不执行 Git。保留 T01 的 Host/Origin 拦截，跨域请求不触发 Git。

## 验证与停止

在临时测试目录建仓库与本地 bare remote，覆盖新增、修改、删除、重命名、暂存加未暂存同一路径、中文、空格、未跟踪、冲突、空仓库、分离 HEAD、无上游、upstream 引用丢失、ahead/behind；含分支合并、标签、本地远端跟踪引用和超过 100 条历史的图夹具。证明只含被允许引用的可达提交、同仓库读取顺序稳定、合并父 OID 正确、截断边界保留。接入检查另测：仓库子目录归根、空仓库可检查、非 Git/bare/无效路径失败不保存、已有历史且有未提交/未推送状态的摘要正确、恶意跨域或超大/非 JSON body 在 Git 前拒绝。Windows 不能创建换行文件名：用原始 porcelain v2 `-z` NUL 字节输入构造换行及重命名双路径解析器夹具，并检查后续显示可安全转义；不要声称 Windows 文件系统换行文件名实测或 Ubuntu 已测。

至少对一次成功 API 读取前后比较临时仓库工作区文件、`.git/index`、引用、配置的内容/存在状态；提供无 fetch/写命令的命令调用证据。API 再测未知 ID、缺 Git/非仓库、超时/输出上限、恶意 Host/Origin；只补 T01 安全回归的受影响部分。可用 Node 内置测试，不安装无必要依赖。不碰真实业务仓库。

结束时停写，回报从 T01 PASS 版本到本次的新增/修改/删除文件与 SHA-256、基线 manifest 是否仍一致、测试命令和实际结果、Windows/其他平台标注、未验证项、是否访问真实项目、当前 Git 状态。只有阶段控制给出 T02 PASS 后，用户可转交 T03。若契约需变更、测试必须访问真实仓库或执行范围外写入/联网，暂停受影响部分并报告，不自行放宽。不要提交或推送。
