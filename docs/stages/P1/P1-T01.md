# P1-T01：配置读取和本机服务安全骨架

将本卡单独交给用户选择的 Gemini 实施。P1 阶段控制负责本卡与阶段验收，总控负责 P1 大阶段总验收。当前可立即执行；P1-T02/T03/T04 尚未解锁。

## 目标、前置和所有权

目标：在独立版本管理工具中建立 `npm start` 本机服务、安全的 `GET /api/projects` 与前端静态资源，为后续接入检查/确认保留严格的 POST 请求边界；保留 `npm run preview` 纯演示。此卡不实现 Git 读取、接入检查/确认、真实前端或材料功能。

前置：核对当前工作目录、无提交状态、根 README 和适用 `AGENTS.md`；阅读 `docs/stages/P1/STAGE_PLAN.md` 第 1–4、7、9 节及本卡。总控正同步更新上位文档；遇到旧“只能手工配置”语句，以本卡明确的新增向导范围为准，不擅自扩大。开始前在 `.local/baselines/P1/` 保存 `package.json`、`README.md`、`frontend/index.html`、`frontend/app.js`、`frontend/styles.css`、`preview.mjs`、`.gitignore` 的原文件副本与相对路径/SHA-256/字节数 manifest；不复制 `.git`、`.local` 旧内容、凭据或其他仓库。记录 manifest SHA-256。原件不能覆盖。

允许写：新建 `server/` 中配置和 HTTP 服务所需文件、对应 `tests/` 中必要接口/配置测试、`package.json` 的 `start` 脚本、`.local/baselines/P1/` 基线。若确需调整 `.gitignore` 只为保持 `.local/` 忽略，可写并说明；现有规则已经忽略 `.local/`。不得改 `preview.mjs`、`frontend/`、根 README、总控文档、本目录阶段文件，也不得新建通用框架、安装依赖。T02 将按顺序接手服务入口。

## 必须实现的契约

- `npm start` 只绑定 `127.0.0.1`，默认端口可为 4189；端口冲突可理解地退出，不杀占用者、不改绑公网。服务从本工具 `.local/projects.json` 读取 `{ "projects": [{ "id": "sample", "name": "示例", "repositoryPath": "绝对目录路径" }] }`。缺文件/空数组为未配置。其他格式错误返回配置错误而非空列表。
- ID 大小写敏感、匹配 `[a-z][a-z0-9_-]{0,31}` 且唯一；名称去空白后 1–80 字符；路径必须是当前主机绝对目录路径，由服务端解析成映射。普通项目列表和后续源码/历史接口只用已登记 ID；仅 T02 专用接入检查可接收用户主动输入的路径，任何接口均不得接受客户端命令。列表不得暴露路径、远端 URL。路径不存在时可保留项目于列表，但未来读取须给明确错误；本卡测试配置解析即可。
- `GET /api/projects` 成功为 `{ "projects": [{"id":"...","name":"..."}], "configured": boolean }`；缺配置/空列表返回 `projects:[]`、`configured:false`，无父目录扫描。配置错误返回非 2xx 与 `{ "error": {"code":"CONFIG_INVALID","message":"中文可理解说明"} }`，不回显 OS 堆栈/路径。
- 服务只给 `/`、`/index.html`、`/styles.css`、`/app.js` 静态白名单，不公开 `.local`、项目根目录或其他文件；GET/HEAD 静态请求即可。后续 Git 与接入 API 可暂返回统一、明确的未实现错误，不能给假成功/零值；本卡不处理它们的路径输入或持久写入。普通未知方法拒绝。
- 每个请求检查唯一精确 Host `127.0.0.1:<实际端口>`。有 Origin 时仅允许 `http://127.0.0.1:<端口>`，`Origin:null` 和外域拒绝；无 Origin 的本机 CLI GET 且 Host 合法时允许。若 `Sec-Fetch-Site: cross-site` 则拒绝。为后续两个 POST 端点实现可复用的前置校验：必须精确同源 Origin、`Content-Type: application/json`（可带 UTF-8 charset）、`X-Local-Intent: project-onboarding`，请求体上限 8 KiB；缺一或超限拒绝，不能进入业务处理。普通 API 非允许方法拒绝。不开 CORS 通配或外域许可。HTTP CSP 只允许同源资源及 `connect-src 'self'`，配合 `nosniff`、`no-store`；现有 `index.html` 的更严格 meta `connect-src 'none'` 本卡不改，由 T04 在页面接入 API 时同步调整。对恶意 Host/Origin 用 403 或等价明确拒绝。
- 当前前端已有“演示模式/演示数据”标识并由原演示 JS 驱动；此卡的真实服务即使提供该页面，也不能将其误称已接入真实 Git。T04 将完成正式真实页面。

## 验证与交付

用 Node 内置测试或等价轻量测试覆盖：缺失/空/格式错误配置、重复/非法 ID、路径绝对性；合法 Host 无 Origin 的 CLI GET、同源 Origin、恶意 Origin/`null`、恶意 Host/端口、跨站 Fetch 元数据；POST 缺 Origin/意图头、非 JSON/超大请求体在业务处理前拒绝；静态白名单、`.local`/遍历/编码变体、其他非法方法；`npm run preview` 原功能仍可启动。验证监听仅 loopback；端口占用错误不通过启动杀进程解决。可以在临时目录构造配置与服务，不访问任何真实业务项目。

结束时停写并回报新增/修改/删除文件、基线 manifest 位置与 SHA-256、修改前后文件 SHA-256、命令与结果、环境、未完成/未验证项、是否访问真实项目、当前 Git 状态。保留可供阶段控制审查的原件和测试证据。只有阶段控制书面给出 T01 PASS 后，用户才能转交 T02。若需要改变接口/安全语义、修改未授权路径、访问真实仓库、联网或执行真实 Git 写入，停止受影响部分并报具体原因，不自行扩大范围。不提交、不推送。
