# P1-T03：确认登记与配置保存

将本卡单独交给用户选择的 Gemini 实施。仅当 P1-T01、P1-T02 由阶段控制记录 PASS，且当前文件与 T02 交付指纹一致后执行。P1 阶段控制验收本卡与集成，总控验收 P1 大阶段。T04 页面卡在本卡 PASS 前不解锁。

## 目标、依赖与文件所有权

目标：把 T02 的只读检查结果经用户主动确认登记到**本工具** `.local/projects.json`，实现 `POST /api/projects`；登记前后被管理仓库的源码、索引、引用和 Git 配置不变。T02 检查失败或用户取消不保存。此卡不写 PC 页面、不添加 Git 写操作、克隆、fetch/pull 或材料目录关联。

开始核对工作目录、`git status --short --branch`、适用 `AGENTS.md`、T02 PASS 记录与文件 SHA-256、`.local/baselines/P1/manifest.json` 原件；发现外部变化先停覆盖。阅读 `docs/stages/P1/STAGE_PLAN.md` 第 3–4、7–9 节及本卡。允许顺序修改 T01/T02 已建的 `server/` 配置/HTTP/票据模块及对应 `tests/`，测试时只写隔离的临时 `.local` 配置。不得写 `frontend/`、`preview.mjs`、`package.json`、根 README、总控文档或本目录阶段文件。生产运行时唯一持久写入是本工具 `.local/projects.json`；锁和临时文件也只在本工具 `.local/`。不覆盖 P1 基线。

## 冻结接口与保存规则

`POST /api/projects` 请求体仅 `{inspectionId,id,name}`，不接受客户端路径、命令或额外字段；成功 `{project:{id,name},alreadyRegistered:boolean}`。ID 大小写敏感且匹配 `[a-z][a-z0-9_-]{0,31}`；名称去空白后 1–80 字符。先执行 T01 的唯一 Host、精确同源 Origin、`Content-Type: application/json`、`X-Local-Intent: project-onboarding` 和 Fetch 元数据校验，8 KiB 体积限制；不满足则在读取票据/配置或运行 Git 前拒绝。无 Origin 的 CLI GET 仍允许，但 POST 必须明确提供合法 Origin 与意图头。

票据来自 T02 成功检查，服务进程内最多 32 个、有效期 10 分钟；不存在/过期/重启失效时报 `INSPECTION_STALE`，不保存。确认时用服务端保存的规范化根重新只读验证：路径仍存在、是非 bare Git 工作树、根与绝对 git-dir 的 `realpath` 均与检查时一致。若被替换、移走、变成非 Git、所有权不安全或不可读，拒绝登记并给明确错误。开发者期间产生新文件/提交不应使身份验证失败，也不要求清理或冻结工作区。确认只登记 root 的规范化路径，不写检查时输入的子目录。

以根 `realpath` 作为重复键，Windows 比较忽略大小写；不同子目录、大小写写法或符号链接归同一项，linked worktree 根不同可分别登记。若根已登记，返回已有 `{id,name}`、`alreadyRegistered:true`，不改旧项目元数据；若提交的 ID 已被另一个根占用，返回 `ID_CONFLICT`，不覆盖。若同一票据已经成功确认，重复/并发确认返回同一已登记项目，不再次写。客户端取消仅丢弃票据、无需修改配置；过期后票据自动失效。

保存时先取得本工具 `.local/` 内独占锁，确保同进程及不同服务实例的两个确认不会相互覆盖；持锁后重新读取最新配置、校验结构和查重。已有配置损坏时报 `CONFIG_INVALID`，原字节完整保留。构造新配置后写同目录临时文件、刷新到磁盘、原子替换；任一阶段失败返回 `CONFIG_SAVE_FAILED`/`CONFIG_BUSY`，旧配置保持原样、清理临时文件、释放锁，不把内存结果当成功。锁释放在 `finally`，陈旧锁不能被静默抢占覆盖，应给可理解的恢复提示。首次成功写入后 `GET /api/projects` 立即可见且重启仍可见；不因打开页面或检查成功自动保存。

除本机 inspect 响应里给用户核对的 `repositoryRoot`，项目列表、确认响应、错误和普通日志均不输出绝对路径、远端带凭据 URL、OS 堆栈。配置中的既有人工项目保持可用，不擅自迁移/清空。明确区分 `CONFIG_INVALID`、`CONFIG_SAVE_FAILED`、`CONFIG_BUSY`、`INSPECTION_STALE`、`ID_CONFLICT` 等错误码；失败不返回假成功。

## 验证、交付与停止

用临时仓库和隔离配置测试：检查失败/取消不创建文件；已有历史、未提交文件和未推送提交在确认前后完全保留；输入子目录最终存根目录；重复根/重复点击/并发票据不新增重复项目；ID 冲突不覆盖；票据过期或身份变化不能登记；配置损坏拒绝覆盖；模拟写入失败后旧登记仍可读；成功后服务重启可列出并读取项目。配置前后比较仓库工作区文件、`.git/index`、引用与 Git 配置的内容/存在状态。跨域/缺 Origin/意图头请求在票据与文件写入前拒绝。只在临时目录制造写入失败，勿改真实业务仓库或本工具实际用户配置。

停写后回报从 T02 PASS 版本到本次的新增/修改/删除文件与 SHA-256、基线一致性、测试命令与真实结果、环境、未验证项、是否访问真实项目和当前 Git 状态。只有阶段控制书面 T03 PASS 后，用户才可转交 T04。若无法安全保留旧配置、需要开放任意路径/目录浏览、联网或写 Git，暂停受影响部分并报具体冲突。不得提交、推送或自动派发。
