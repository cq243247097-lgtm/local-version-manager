# P1 技术输入：真实 Git 只读工作台

> 此文件不再直接派给 Gemini。保留技术约定作为阶段控制的细化输入；协作、所有权和派发规则以 [实施总方案](IMPLEMENTATION_MASTER_PLAN.md) 与 [P1 阶段控制交接卡](P1_STAGE_CONTROL.md) 为准。Gemini 仅执行阶段控制在 docs/stages/P1/ 生成的单任务卡。下文旧单包范围不授予整体实施权限。

## 身份、任务和输入

实施者：用户指定的 Gemini（具体型号/推理设置由用户记录）。任务与阶段验收者：P1 阶段控制会话；大阶段总验收者：当前总控 Codex 会话。仅实施 P1，不顺带执行后续阶段。

在用户已打开的“版本管理工具”独立项目内工作。先读根 `README.md`、`docs/PROJECT_PLAN.md` 第 1–7 节，再按需读现有前端与预览入口。不得加载其他业务项目的整套说明、源码或历史聊天。

目标：保留确认过的 PC 界面，增加独立本机服务，把源码区域接到真实的本地 Git 只读数据。安装包和升级包仍是明确标注的演示，不能混入真实项目概览。

## 开始前的基线

1. 检查当前目录、`git status --short` 和是否有新的 AGENTS.md。当前仓库可能尚无提交，所有现有文件可能仍未跟踪，不要据此覆盖它们。
2. 在 `.local/p1-baseline/` 保存将修改文件的原始副本和相对路径/SHA-256 清单；不要复制 `.git`、秘密或其他项目。这个快照只用于 Codex 比较，没有授权时不以创建 Git 提交替代。
3. 简述理解的目标、可写范围和下一动作后开始；存在实质契约冲突才提问，不在每个步骤反复等待批准。

Gemini 是 P1 的唯一代码写入者，可修改 `frontend/`、`preview.mjs`、`package.json`、`.gitignore`、根 `README.md`，可创建 `server/`、`tests/` 和 `docs/P1_DELIVERY.md`。`.local/` 仅用于本机配置、基线和临时验证资料，不进入 Git。

方案书与本任务书由 Codex 维护；发现需要修改，先反馈原因，不自行改变验收标准。不得修改同级进销存项目、原演示副本、真实归档、全局 Git 配置或机器安全设置。不提交、不推送、不删除原文件，不部署、不安装未知程序、不启用调度。

## P1 最小契约

### 配置和模式

- 服务端读取 `.local/projects.json`，形状为 `{ "projects": [{ "id": "sample", "name": "示例", "repositoryPath": "用户显式填写的仓库绝对路径" }] }`。配置不含 token/密码，也不在前端硬编码盘符。
- 配置缺失/为空时展示“接入已有项目”向导，用户输入本地路径，先只读检查并核对摘要，确认后登记本工具配置。不扫描父目录、不自动选进销存仓库，不增加任意磁盘目录浏览器。具体接入 API、校验和保存契约由阶段控制在单任务卡细化。
- `npm start` 启动真实只读服务，仍仅 loopback；`npm run preview` 保留现有纯演示。端口冲突清楚报错，不能杀掉占用者或暴露到局域网解决。
- 前端区分演示与真实只读；真实模式禁用/隐藏模拟提交、模拟推送和伪造场景切换。材料区域明确仍为演示；不得把它们标为当前真实项目的材料。

### HTTP 接口

使用 JSON，同源 API；可按现有运行入口组织代码，不引入多余的服务层级。以下名称与语义是本阶段约定：

- `GET /api/projects`：项目 `{id,name}` 列表，不返回仓库绝对路径或带凭据的远端 URL。
- `GET /api/projects/:id/source`：本地快照，包含 `scannedAt`、`branch`、`headState`（`attached|detached|unborn`）、`changes`、`changedCount`、`upstream`。
- `changes` 每项包含稳定的 `path`、可空 `oldPath`、Git 索引与工作区状态 `indexStatus/worktreeStatus`；同一路径不重复计数。可附 `conflicted`，不能隐藏冲突。忽略文件不计数，未跟踪文件按文件列出。
- `upstream` 包含 `state`（`available|not-configured|unavailable`）、可空 `name/ahead/behind`；非 available 的数量为 null。标签标明本地跟踪快照，未联网核实。
- `GET /api/projects/:id/history`：最近最多 100 条可达提交，包含 `oid`、`parents`、`subject`、`committedAt` 及引用 `refs`（name/oid/kind），附 `truncated`。明确图的范围，不伪造未返回的关系；无提交返回空列表与说明。
- 非法项目 ID 返回 404。缺 Git、非仓库、读取失败等返回明确错误码和可理解消息，不把操作系统堆栈或秘密回显。前端须显示错误和重试入口，不能转成零值或演示成功。

不新增 diff 内容读取接口：第一阶段“查看改动”展示真实文件列表和状态即可，删除真实模式中的示意差异。真实文件内容查看可后续按用户需求增加。

### Git 读取和图

复用已安装 Git，使用参数数组、`shell:false`，合理限制子进程耗时和输出；超限显示明确状态，不静默截断计数。禁用可选锁和交互提示，不执行外部 diff/textconv、hooks 或 shell 命令。

使用 porcelain v2 与 `-z` 一类机器接口解析状态，正确处理重命名双路径、中文、空格与换行。未提交计数使用解析后的变更记录，不用文本行数。未出生分支、分离 HEAD、无上游和冲突均单独处理。

提交图根据返回的父 OID 与引用绘制，不使用假数据的固定行号连线。历史截断处可显示继续到窗口外，不把未加载祖先当成版本起点。展示当前分支、远端跟踪分支及标签；不要把“本地 origin 引用”描述为实时远端状态。

### 本机接口边界

普通业务接口只读取服务端登记项目，不接受客户端仓库路径或命令。专用接入检查/确认端点可接收用户主动输入的本地目录，仅用于只读识别与确认后登记本工具配置；不得变成任意文件读取或命令执行接口。校验 Host/Origin，明确配置写入的抗跨站策略，拒绝外域访问；静态文件白名单，不暴露 `.local` 或项目源码。保留 CSP，将需要的同源 API 连接放开即可，不放开任意外部连接或脚本。

路径和提交说明以文本渲染。遇到 Git 目录所有权限制时返回说明，不修改全局信任配置。刷新只重新读取本地状态，不执行 fetch。

## 定向验证与验收标准

只在临时目录创建测试仓库、文件与本地 bare remote，不用真实业务仓库做 Git 写入测试。允许用 Git 初始化/提交临时夹具；这不授权提交本工具或其他真实项目。

| 证据 | 必须证明的行为 |
| --- | --- |
| 状态夹具 | 新增、修改、删除、重命名；同一文件暂存和未暂存只计一次；中文/空格/换行路径正确 |
| 特殊仓库状态 | 空仓库、分离 HEAD、无上游、冲突不被误报为已同步 |
| 本地远端夹具 | ahead/behind 正确，未联网时始终标注快照，不产生 fetch/写命令 |
| 提交图 | 含分支/合并的夹具父子关系正确，引用准确，截断有标记 |
| 只读检查 | 一次接口读取前后工作区文件、索引和引用无变化；不改 Git 配置 |
| 接口边界 | 未配置、未知 ID、越界静态路径、恶意 Origin/Host 被正确处理，错误不伪造成功 |
| 桌面浏览器 | 页面可打开、项目切换与刷新有效、文件列表正确、真实模式无模拟写入、材料仍明确为演示、控制台无相关错误 |

优先使用 Node 内置测试和已有浏览器工具，不为重复证明同一行为增加多层测试。仅当依赖实际必要时说明后再引入。无 Ubuntu 环境就写未验证，不伪造跨平台通过；PC 验证足够，不做手机端。

## 完成与停止

完成后停止代码写入，提交 `docs/P1_DELIVERY.md`，内容只需：

1. 实际完成和未完成项；Gemini 型号（若可得）。
2. 修改/新增文件及基线快照位置，必要接口说明。
3. 启动与验证命令、环境和真实结果，桌面截图位置。
4. 未验证项、已知缺陷、依赖变更；是否访问过任何真实项目。
5. 当前 Git 状态与“已停止写入，等待 Codex 验收”。

需要写入真实仓库、联网获取、扩大路径范围、修改上述接口语义或加入后台自动行为时，暂停受影响部分，交给用户与 Codex 判断。可在范围内修复的已知错误继续调试；不要为了按时交付弱化验收或把失败标成通过。
