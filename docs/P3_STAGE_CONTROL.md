## 必须细化的操作契约

1. **本地提交**：选择哪些文件，已有暂存区内容如何处理，暂存与未暂存并存、删除、重命名、未跟踪与冲突时的语义；提交说明、空提交、未配置身份和分离/未出生 HEAD 的行为。预览必须反映实际待提交内容，不可偷偷提交用户未选择的暂存内容或清除既有暂存工作。不能只做 add-all + commit。
2. **确认与并发**：先展示服务器核实的项目、分支及操作范围，再确认；确认绑定仓库身份与相关 Git 状态。预览后发生变化时重新检查，不对不同 HEAD/索引盲写。重复点击、重试、服务重启和超时不得造成重复提交或未知状态被当作失败重做。应用内部互斥不等于能锁住外部 Git 客户端；明确可检测条件与残余竞态，不宣称系统级事务。
3. **Git 调用边界**：不能复用只读 runGit 的全部配置直接执行写操作。明确 hooks、fsmonitor、签名、用户身份、凭据助手和外部程序的策略。不得为了成功而静默禁用用户签名/提交钩子、改全局配置或自动启动任意项目脚本；无法安全支持的配置可明确拒绝，给可理解原因。先冻结首版支持范围。
4. **推送（若选入）**：明确 remote、来源分支、目标引用、上游设置与非快进拒绝；不猜默认目标，不强推。认证失败/远端拒绝/网络超时后区分已知失败与结果未确认，重新读取可确认事实，禁止假成功或自动无限重试。凭据不能写到配置、日志或响应。
5. **fetch（若选入）**：明确它会联网并更新本地远端跟踪引用；不混入普通刷新，不自动 prune、不合并代码。遵守凭据与输出/时间预算。
6. **分支（若选入）**：新分支名称、起点和是否切换分开明确；切换遇到未提交/冲突时保守阻止或说明保留条件，不自动 stash、清理或覆盖。现有分支重名、非法名、worktree占用给真实错误。
7. **接口与UI**：只从已登记项目ID定位仓库，不接受任意命令/参数/路径；写端点专用意图、严格字段、Host/Origin、请求上限与服务端校验。GET不得写Git。保留演示隔离，真实失败不退回假数据；提示完成后刷新真实状态。面向新手解释影响，避免把内部实现术语堆进用户流程。
8. **失败恢复**：多步操作部分完成时保留用户工作，不用隐式reset回滚；记录最小操作结果并核对磁盘事实。稳定错误代码与结果状态应能区分未执行、已完成、部分完成、结果未知。定义有限超时/输出边界及子进程退出处理。
