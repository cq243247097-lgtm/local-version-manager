## 必须冻结的契约

1. **记录来源**：真实用户材料格式优先，不能假设已有 manifest。只读读取明确来源的元数据；无声明的文件仍可列出名称、类型、大小与待识别状态，不从目录/文件名推导精确版本、源码提交或验证通过。若引入可选示例记录格式，说明它是工具可识别格式，不要求改写旧材料，也不将未经验证的旧格式声称适配成功。
2. **事实分层**：文件存在、记录声明、完整性记录、安装验证记录分开。P2 只能展示“记录称通过/未核验当前文件”等有来源的事实，不能伪装本工具本次已校验或安装成功。文件已变化、记录引用缺失和记录冲突须有清晰状态。
3. **升级兼容**：目标版本 → 最低支持来源版本，例如 `v1.4.0 → v1.2.0`，折叠后可见。只从明确直接支持列表计算；不推断连续区间，不把声明当作实测。多个包/修订不同声明分别显示，无声明待确认、没有包暂无升级包。列表为空与未知区分；声明含不支持的范围或不可比较版本时不要部分忽略后给出看似完整的最低值。
4. **版本比较**：明确可接受语法、v 前缀、补丁位、预发布/构建标识和非法值规则。不能直接复用演示字符串排序。尽量限制首版格式而非自行做通用语义版本解析器；超出格式的记录保留可理解提示，不丢文件。
5. **扫描边界**：明确每类根目录、遍历深度、条目/字节/时间上限、稳定排序、部分结果与截断标志。默认不跟随符号链接、junction 等越界入口，不读取任意声明引用的绝对路径或 `..`。单文件不可读不能伪装空目录；变化中的文件、消失目录与不完整扫描不可呈现为全量成功。
6. **标识与切换**：项目、安装包、升级包和修订关联清楚；API/前端使用同一份计算结果产生最低摘要和详情。切换项目、切换材料类型、并发刷新、旧请求返回和重试不混用其他项目的数据。
7. **路径与隐私**：原始包不经静态服务器暴露；显示相对路径，只有用户关联确认时展示必要绝对根。元数据只作文本/数据，不作为命令、可执行脚本或页面 HTML。
