# 新手操作指南

## 1. 先分清四类目录

- **工具源码**：本工具的 `server`、`frontend`、`package.json` 和 `preview.mjs`。
- **工具数据**：项目路径配置及提交、材料操作记录。默认放在工具目录的 `.local` 中。
- **被管理源码**：你自己的 Git 项目，包含 `.git`、代码和未提交修改。
- **材料和归档目录**：安装包/升级包原文件，以及你另外选择的归档目标。

不要把工具数据放进被管理源码或材料目录，也不要把归档目标放在其中。材料操作会拒绝不安全的重叠路径。使用当前用户独占的本地目录，操作期间不要让另一个工具同时改动这些文件。

正式使用前分别备份这四类内容。复制工具程序不等于备份了项目或安装包；只备份 projects.json 也不等于保留了操作记录。配置及记录可能含本机路径、提交说明等信息，不要连同密钥、令牌、真实材料一起上传公开仓库。

## 2. 准备和启动

本版交付的是源码，不是双击安装包。不自动安装 Node、Git 或浏览器扩展，不需要 Electron，也不需要安装 npm 依赖。

在终端检查：

```sh
node --version
git --version
```

Linux 实测 Node.js v24.19.0、Git 2.52.0。其他版本尚不保证兼容；Windows 示例只是操作说明，不是实机通过证明。

把交付内容放在全新的独立目录，再运行。旧 Windows 工作目录曾存在与本次交付不相干的 master 历史；不要尝试在那个原目录通过 `git pull`、`git reset` 或覆盖文件来“对齐”。新建副本，或将已明确发布且包含本次交付的版本克隆到新目录，保留原目录作为备份。本指南不承诺未发布的改动能从远端取得。

在工具目录运行：

```sh
npm start
```

打开 `http://127.0.0.1:4189/`，这是会操作真实本机数据的模式。服务只监听本机 127.0.0.1，不是局域网或手机服务。

只看虚构演示：

```sh
npm run preview
```

打开 `http://127.0.0.1:4191/`。演示不调用真实 API，不会提交代码、校验或归档真实材料。演示里的模拟推送也不代表真实模式支持推送。

从其他目录启动时，可以直接调用绝对路径：

```sh
node /absolute/path/to/local-version-manager/server/index.js
node /absolute/path/to/local-version-manager/preview.mjs
```

默认配置始终是**工具目录**下 `.local/projects.json`，不随终端所在目录改变。首次没有配置是正常状态，可直接开始接入项目。

### 自定义端口和数据位置

Linux/macOS 终端语法示例（路径需要换成自己的）：

```sh
PORT=4201 LVM_CONFIG_PATH=/absolute/path/to/tool-data/projects.json node /absolute/path/to/local-version-manager/server/index.js
PORT=4202 node /absolute/path/to/local-version-manager/preview.mjs
```

PowerShell 语法示例（尚未 Windows 实测）：

```powershell
$env:PORT='4201'
$env:LVM_CONFIG_PATH='C:\example\tool-data\projects.json'
node 'C:\example\local-version-manager\server\index.js'
```

`PORT` 必须是 1–65535 的十进制整数，不能留空、带空格或小数。`LVM_CONFIG_PATH` 必须是本机绝对**文件**路径，不能是相对路径或空字符串。它用于真实服务，演示不读取项目配置。取消自定义时删除环境变量，不能把值设为空。两个进程若继承相同 PORT 仍会冲突；未设置时两个默认端口可以同时使用。

停止时按 Ctrl+C，等待终端退出。关闭浏览器不会停止服务器，也不会取消正在执行的请求。正常停止会等待当前请求；强行杀进程可能留下需要核对的操作。

## 3. 接入已有 Git 项目

1. 在真实工作台打开“接入已有项目”，输入本机已有项目的绝对路径。
2. 点“检查目录”。如果输入子目录，核对页面解析出的真正仓库根目录、当前分支和最近提交，避免接错项目。
3. 确认名称后点“确认接入”。工具保存路径配置；已有开发历史、未提交修改和未推送提交不会因登记而被重置。

不支持远程 URL、裸仓库、不存在的路径。非 Git 目录不会被自动初始化。重复接入同一仓库会复用登记。Ahead/Behind 仅比较本机已有跟踪引用，没有联网核实远端是否更新。

## 4. 选择文件并做本地提交

提交会修改真实 Git 仓库。先确认项目和分支正确；不要同时在其他程序执行提交、切分支或暂存操作。

1. 在“源码工作台”打开“选择文件并本地提交”。默认不选择任何文件。
2. 勾选需要的文件，填写 1–500 字的单行说明。不能选择的项目会说明原因；重命名必须成对处理。
3. 点“预览本地提交”。逐项看服务器给出的实际范围，尤其是已暂存部分与未暂存部分。HTTP 页面预览是文件级范围，不提供逐行 diff，也不是“勾选后自动包括此文件所有修改”。
4. 确认无误才点“确认本地提交”。未选中的已暂存内容会保留；这不是把整个暂存区都提交。取消预览不写 Git。
5. 等待查询结果确认 completed 和提交编号，再核对刷新后的状态、历史。

仓库在预览后变化会使预览失效，需要重新检查。当前拒绝缺少提交身份、冲突或进行中的合并，以及 hooks、签名、外部 filter、fsmonitor、稀疏检出、子模块等不支持情形；工具不会替你关闭这些配置。不要为了通过工具检查随意修改业务仓库安全设置。

断线、超时或刷新页面后，使用“查询原操作结果”，不要再次确认或换新操作 ID 重做。浏览器会保留必要的原操作绑定；请使用同一浏览器与服务地址，不要清除站点数据。无法保存操作 ID 时，界面会阻止确认。

- completed：本次提交结果已核实。
- partial：存在已核实的部分副作用，可能已暂存部分文件。只以页面列出的具体变化为准，不代表整次成功。
- unknown：不能确定是否已经写入。保留记录，核对本地 Git，不要盲目重试。

## 5. 关联和查看材料

在“安装包资料库”或“升级包资料库”进入关联目录向导，输入本机已存在的材料根目录；先做只读检查，再核对规范化路径并确认保存。更换原有关联要明确确认。此步骤改的是工具配置，不改材料目录。

扫描默认有深度和数量限制（5 层、单目录 1000 项、总计 5000 项）；出现截断提示时，不能据此断定目录已全部检查。目录里没有登记的文件显示为待识别；空目录、损坏声明或冲突声明会保留相应提示，不会猜测版本和可信来源。

看材料时分清：

- 文件存在：只说明当前扫描找到了文件及大小、时间等属性。
- material-records.json 的来源/版本/源码关联：是材料随附的声明，不是认证。
- 历史完整性记录：记录说通过，不等于当前文件刚被重新计算检查。
- 安装验证登记：是某个时间、环境的历史测试说法。本工具不会运行安装包证明它仍能安装。
- directFrom 和最低直接来源版本：来自登记的直接升级声明，不表示未列出的版本也能升级。

## 6. 单文件摘要与非覆盖归档

本节对应已实现的核心、API 和页面流程；代码/API 独立审核已完成，真实浏览器全流程及 Windows 最终验收仍待完成。若打开的版本没有这些入口，先核对是否取得了本次完整交付，不要使用演示按钮代替真实操作。

页面入口与操作顺序：

1. 在安装包或升级包详情选择“校验单文件完整性”或“预览非覆盖归档”。
2. “可信基准”默认“无基准（默认）：仅计算摘要”。需要比对时，主动选“明确采用历史登记摘要”（有可用声明时才显示）或“手动输入可信 SHA-256 与来源”，核对来源；归档还要输入现存目标目录。
3. 点“预览操作”，核对服务器结果，再点“确认校验”或“确认复制归档”。想修改时点“返回修改（废弃预览）”；放弃则点“取消，不执行”。
4. 执行后可“查询原操作结果”或“请求取消原操作”。“关闭（保留原操作查询）”仅关闭对话框，不取消执行。
5. 刷新后先切回原项目和材料种类，再用材料页面顶部“查询上次材料操作”恢复，目录重新关联或不可读时也保留这个入口。只有原 ID 查询返回 completed 后才允许明确新操作替换保存的 ID；其他状态或查询失败都先核对原 ID，不另建操作。

结果不会自动持续刷新；仍在处理中时，点击“查询原操作结果”继续核对。浏览器只保存项目/材料种类对应的操作 ID，不保存完整材料路径或内容；请保持同一浏览器和服务地址，不要清除站点数据。

### 摘要和基准

SHA-256 可以理解为文件内容的指纹。检查前明确选择是否采用基准：默认无基准；采用声明或手工输入时，必须明确确认 64 位十六进制摘要及其来源说明。工具不会把刚算出来的摘要自动当成可信基准，也不会自动采用旧登记里的摘要。

预览核对具体文件、采用的基准及预算，之后明确确认才执行。只处理单个普通文件，不解压、不运行它。

- matched：那次计算与明确选用的基准一致。仍取决于基准来源是否可信，不证明安装或升级成功。
- mismatched：不一致；不要把材料当作已通过，归档不会发布。
- no_baseline：已算出指纹，但没有比对基准，**不是校验通过**。
- changed/unreadable：读取时文件变化或无法读取，不能给通过结论。
- timeout/limit_exceeded/cancelled：超时、超出资源上限或取消，不能当成功。

查询显示的是“上次检查”的时间和事实，不会自动重新计算内容。即使关联仍相同，文件后来也可能变了；需要证明当前内容时，必须另行明确预览并执行。

### 归档的含义

归档是把单个文件复制到你明确指定的独立目录，**保留原文件，不覆盖旧目标**。目标目录必须已经存在，不能与任何已登记源码、材料根或工具操作数据目录相同或相互嵌套。目标文件使用源文件名，本版不提供任意改名或覆盖选项。

预览时核对源文件、目标目录、文件名、来源声明和冲突规则，再确认执行。工具先复制到私有暂存位置，复读核对摘要后，使用文件系统硬链接进行不覆盖发布。

- published：那次已发布副本。无基准时只证明复制检查一致，不证明发行来源可信。
- duplicate：已有同名目标的内容相同，保留原目标，不再覆盖。
- conflict：已有同名目标内容不同，保留原目标，停止发布。
- unavailable / SAFE_PUBLICATION_UNAVAILABLE：文件系统不支持所需安全硬链接发布。请另选合适的本地文件系统；工具不会降级成覆盖复制。
- unknown 或 partial：发布或记录可能已发生部分变化，先核对，不能当普通失败重做。

结果中的“声明”不会变成安装通过记录，也不会补造 directFrom。源包、P2 登记和旧归档目标均不因本操作被替换。

### 预算、取消和中断

默认每个文件最多 1 GiB（1,073,741,824 字节），一次执行预算 60 秒，以 64 KiB 块处理。预览票据约 5 分钟有效。归档还需要复读暂存及可能已有的目标，会消耗同一次时间预算；不是保证 60 秒内一定完成或一定返回。当前页面没有提高这些上限的设置。

同一服务实例同一时间只处理一个材料操作，没有后台队列；不同服务实例不保证全局互斥，不要并行启动多个写入者处理相同材料。

取消是协作式的，要等程序到检查点，不能强行打断挂起的磁盘调用。取消预览不执行；确认之后关闭窗口不等于取消。发布之后收到取消或超时，副本可能已经存在，结果会保留已发布事实，不自动撤回。

网络断开后，保留 projectId、材料种类和原 operationId，用同一个 ID 查询，不生成新 ID 重做。completed 只表示流程结束，不等于摘要匹配或归档已发布，要继续看各项结果。not_started 表示查询当时尚无持久记录，之前的确认仍可能稍后开始，因此也不能换新 ID 重做。running 表示正在处理；服务重启、其他实例查询旧 running 等情况可能显示 unknown，不能据此推断“没有复制”。相同 ID 不会重新执行操作，也不会修复后来被人删除的目标。

成功后也可能留下空暂存目录；重复、冲突、失败或中断时可能留下暂存文件。工具不自动删除未知文件、清理遗留锁或修复归档。先保留工具记录和现场，人工核对后再决定如何处理，不要看到暂存文件就批量删除。

## 7. 工具数据、容量与迁移

默认数据布局：

```text
工具目录/.local/
  projects.json          项目和材料路径配置
  commit-operations/     本地提交日志及锁等记录
  material-operations/   摘要和归档操作记录
```

设置 LVM_CONFIG_PATH 后，两个操作记录目录也位于该配置文件的同级目录。不要只移动配置而遗漏记录，否则无法可靠查询原操作。工具记录不能替代源码、材料的备份。

材料记录默认最多 1024 条，每条最多 32 KiB；容量满后拒绝新操作，不自动轮换删除。提交记录另有最多 100 条活动记录、64 MiB 日志上限；已核实且超过 7 天的完成记录可以在内部退役，日志与防重放信息仍保留，并非可无限使用。容量错误不是让你删除数据目录重试的指令，应先备份并核查，不要抹掉未决操作的身份。

迁移步骤：

1. 查询并记录未完成的操作；停止服务，等待正常退出。
2. 分别备份工具数据、源码仓库和材料。复制程序时不要把私有数据当作公开交付文件。
3. 把程序放在新目录；需要保留旧登记时完整迁移数据，或用 LVM_CONFIG_PATH 指向原来的绝对配置路径。
4. 启动并检查输出的配置位置。项目和材料路径不会自动重写：原路径失效时重新选择现有目录，不要为消除错误而覆盖原仓库或删除操作记录。
5. 先在临时副本确认读写流程，再使用正式数据。

纯运行所需文件是 package.json、preview.mjs、server/、frontend/；建议同时保留 README、docs 和 tests 方便查阅与验证。无需搬移 node_modules，不把开发用 .git 或私有 .local 当作通用分发要求。

## 8. 常见问题

- **命令不存在**：检查 Node/Git 是否安装及终端 PATH，重新开终端再查询版本；工具不自动安装环境。
- **端口被占用**：先确认是否已有服务在运行，或换一个 PORT。不要随意结束不认识的进程。
- **页面是虚构项目**：你打开了 preview；真实模式默认是 4189。
- **配置损坏**：保留原文件并从备份核对；工具拒绝覆盖损坏配置，不要清空它“修复”。
- **PATH_UNAVAILABLE / MATERIAL_ROOT_UNAVAILABLE**：路径移动、删除或权限改变。检查真实位置和权限，再重新选择项目或关联材料目录。
- **预览过期或内容变化**：回到选择步骤重新预览。若已经发出确认，先查询原 ID，不要直接重做。
- **记录忙、容量满、损坏或持久化失败**：停止新的写操作，保留现场与原 ID；核查原操作、目录权限和备份。不要自动清锁、删记录或重新初始化存储。
- **没有“成功”但看见归档文件**：可能已发布而最终记录失败，或取消来得太晚。按 partial/unknown 处理，不覆盖或删除它。

## 9. 尚未保证的事情

已做的 Linux 代码/API/启动测试不替代真实浏览器验收，也不替代 Windows 的路径、权限、junction 和硬链接实机测试。静态页面断言通过也不是用户完整点击流程通过。

操作记录的持久性范围是服务进程退出/重启且操作系统和文件系统仍正常运行；不承诺操作系统崩溃、断电或网络文件系统下的数据恢复。目录和文件身份检查能发现多类变化，但便携 Node 接口不能彻底排除恶意瞬时路径替换（TOCTOU）；不要把它当作操作系统权限隔离。

不要把“文件存在”“复制完整”“摘要匹配”“来源可信”“安装通过”“升级兼容”当成同一件事。本版不执行安装包或业务脚本，也不替你完成真实安装、升级验证。
