# 本地版本管理工具

独立于被管理软件的桌面浏览器工具。提供 PC 端本地项目源码状态查看、接入向导与真实 Git 历史拓扑图，同时保留纯交互演示入口。查看默认只读；本人选择文件、审查服务器预览并明确确认后，可在当前分支执行本地提交。本批无推送、fetch、拉取或分支写操作，不连接远端，不开发手机端。材料目录始终只读。

---

## 快速启动

本项目无需安装任何第三方 npm 依赖（仅使用 Node.js 原生标准库），提供以下两套启动入口：

### 1. 真实本地工作台（推荐）

```sh
npm start
```

- **默认访问**：[http://127.0.0.1:4189/](http://127.0.0.1:4189/)
- **模式**：真实模式（Real Mode）
- **功能特性**：
  - 本地已有 Git 项目接入向导（路径检查、工作树核验、确认登记）；
  - 多项目切换与自动记忆；
  - 真实 Git 工作区状态查看（未暂存/暂存文件、25 格文件状态提醒、未提交文件清单）；
  - 多分支与合并历史拓扑图（真实父子边、本地分支/上游跟踪引用/附注标签徽标、超过 100 条安全截断与窗口外父提交标识）；
  - 本地快照上游差异（Ahead/Behind）展示；
  - 选中文件的真实本地提交：默认不选文件，服务器预览后明确确认，再查询持久化操作结果并刷新真实状态/历史；
  - **安装包资料库**：真实只读物理扫描、版本/修订分组、空子目录展示、事实分层检查（物理探测、历史完整性与安装验证登记、“记录称通过，本次未核验当前文件”警示）；
  - **升级包资料库**：增量升级包真实树形、基于记录 directFrom 计算声明的最低直接来源版本、支持直接升级版本明细表格；
  - **材料关联向导**：支持对各项目独立关联安装包/升级包物理根目录，具备两步核对与安全确认；
  - **根失效恢复**：材料物理目录移动或无权限时，提供明确 409 提示、重试与重新关联入口。
- **端口自定义**：可通过环境变量 `PORT` 更改真实服务端口；主机固定绑定 `127.0.0.1`。两个入口默认都使用 4189，不能同时占用该端口；若要同时运行，请为真实服务设置其他端口。

### 2. 纯交互演示（原型演示）

```sh
npm run preview
```

- **默认访问**：[http://127.0.0.1:4189/](http://127.0.0.1:4189/)
- **模式**：演示模式（Preview Mode）
- **功能特性**：保留原有无状态纯前端演示，使用虚构数据在浏览器内存中演示场景切换、模拟提交、模拟推送、安装包树与升级包兼容摘要。所有操作刷新即重置，不读写本地文件或 Git，不调用任何后端 API，无真实向导弹窗。

## PC 接入向导与材料关联向导

### 1. 接入本地 Git 项目

在真实模式（`npm start`）下，首次进入或点击导航栏“接入已有项目”即可打开接入向导：

1. **输入本地绝对路径**：
   - Windows 示例：`D:\projects\my-app` 或 `D:/projects/my-app`
   - POSIX 示例：`/home/user/projects/my-app`
   - **输入限制**：必须是本地已存在、具有实际工作树的普通 Git 仓库根目录或其子目录。
   - **不支持**：远程 URL（如 `https://...`、`git@...`）、裸仓库（Bare Repository）、非目录路径或不存在的路径。
   - **不执行自动初始化**：若目标路径非 Git 仓库，向导会给出明确错误提示，不会擅自执行 `git init`。
2. **检查目录**：
   - 点击“检查目录”，向导通过 `POST /api/projects/inspect` 安全检查目标路径；
   - 若输入的是仓库子目录，服务端会自动解析并醒目提示规范化后的真实仓库根目录（`repositoryRoot`）；
   - 展示工作树身份摘要：当前分支（或分离 HEAD / 初始未出生状态）、最近提交信息、工作区未提交文件数、相对本地跟踪引用的 Ahead/Behind 状态（注：此为本地快照，不联网核实）；
   - 明确提示：已有的开发历史、未提交修改和未推送提交均会完整保留。
3. **确认登记**：
   - 核对项目名称（可自定义）与候选项目 ID；
   - 点击“确认接入”完成登记。工具将该项目记录持久化至 `.local/projects.json`；
   - 登记成功后自动刷新工作台并切换到该项目。若该仓库此前已登记，则直接切换并复用已有配置，不产生重复条目。

### 2. 关联安装包与升级包物理目录

当项目尚未关联对应材料目录时，进入“安装包资料库”或“升级包资料库”将显示未关联引导态，点击“关联目录”即可打开向导：

1. **输入材料根目录绝对路径**：
   - 输入本地计算机上的真实安装包/升级包根目录（例如 `D:\materials\installers`）；
   - 点击“开始只读检查”，服务端校验路径、解析挂载点并启动有界只读扫描。
2. **审查扫描与识别摘要**：
   - 页面展示规范化后的真实物理根路径；
   - 展示扫描摘要：已发现文件数、目录数、已识别记录数、待识别文件数、缺失引用数等；
   - 若当前项目此前已有关联目录，界面会醒目提示“更换已有关联目录”及原关联路径；
   - 若扫描因达到深度（5 层）或目录上限（1000 项）发生截断，明确展示截断原因。
3. **确认关联**：
   - 点击“确认关联并保存配置”，前端仅将检查票据 `inspectionId` 及 `replaceExisting` 发送至服务端（不传递任何路径）；
   - 成功后自动重新加载材料树形视图；材料目录本身绝不被写入或修改。

## 事实分层与材料只读语义

1. **只读保护与零污染**：
   - 本工具对安装包和升级包物理目录仅执行有界只读扫描（只读探测文件存在性、修改时间与大小）；
   - 绝不执行材料包程序、绝不计算耗时哈希、绝不下发下载/执行动作、绝不向材料目录写入或修改任何文件。
2. **三层事实严格隔离**：
   - **第一层：本次物理文件（只读探测）**：仅反映当前磁盘上该文件是否存在，以及属性是否与登记一致；
   - **第二层：完整性记录（历史登记）**：读取目录下的 `material-records.json` 登记信息。即使记录写明 `passed`，界面必须且已明确标注：**“记录称通过，本次未核验当前文件”**；
   - **第三层：安装验证记录（历史登记）**：展示历史测试环境与结论。记录属性一旦与物理文件不符，界面醒目提示“属性需复核”，绝不显示绿色“可用”。
3. **待识别与异常文件容错**：
   - 未在记录中声明的真实物理文件，归入“待识别材料”分组，不猜测版本号、平台或来源；
   - 空子目录保留在树中并标注“空子目录”，不静默遗漏；
   - 记录冲突（多条声明指向同一文件）或记录损坏时保留物理文件并提示异常，不破坏呈现。
4. **升级包最低直接来源版本**：
   - 基于 `material-records.json` 中 `directFrom` 数组由服务端版本算法精确计算（SemVer / 数字分段版本）；
   - 折叠条目及详情页明确展示 API 给出的 `minimumDirectSource`，不前端自算排序；
   - 未声明直接来源或版本不可比较时，明确标明“待确认”或“需核对”；同目标版本不同修订独立列出，绝不合并。
5. **根不可用与故障恢复**：
   - 当关联的材料目录被移动、删除或无权限访问时，服务端返回 409 `MATERIAL_ROOT_UNAVAILABLE`；
   - 前端展示明确错误面板，提供“重新关联目录”和“重试读取 ↻”按钮，引导用户平滑恢复。

## 选择文件并本地提交

在真实模式的“源码工作台”点击“选择文件并本地提交”：

1. 逐项勾选服务器列出的候选文件（默认全不选），填写 1–500 字单行说明。重命名旧/新路径成对选择；不可选原因直接显示。
2. 点击“预览本地提交”，核对服务器确认的项目、分支、说明及文件级实际范围。HTTP 预览不含逐行差异。未选中的已暂存工作会保留。取消或关闭预览不写 Git。
3. 点击“确认本地提交”后才执行写入；只有查询接口核实 completed 才显示成功与提交 OID。完成后读取真实状态与历史；刷新失败保留操作结果并可重试读取。
4. 失效预览必须重新生成。断线、超时或页面重载后，用浏览器保留的原操作 ID 查询，绝不自动再次确认；重新打开此入口即可查询。请使用同一浏览器和服务地址，勿清除站点数据。无法保存操作 ID 时不发送确认。
5. partial 表示已有部分暂存变化；unknown 表示结果尚不确定，两者均需核对本地仓库，不是“失败后可重试”。partial 页面仅列出服务器本次核实的具体暂存变化文件，不把整个选择范围当作已暂存；结果转为 unknown 或查询中断时不再展示旧的部分暂存清单。

当前不支持无提交身份、冲突/进行中的合并、签名、hooks 等配置，拒绝时不会替用户更改配置。仅提供服务进程崩溃后的结果核对，不保证操作系统崩溃或断电恢复。Windows 原生运行仍需在目标机器最终验证。
