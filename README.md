# 本地版本管理工具

在自己电脑的浏览器里查看已有 Git 项目、选择文件做本地提交，并管理安装包和升级包材料。不需要 Electron，也没有自动安装程序；交付形式是源码加 Node.js 运行环境。真实模式不会自动联网拉取或推送。

首次使用建议先用临时项目和材料副本试一遍。正式使用前备份源码（包括 `.git` 和未提交文件）、材料、工具配置及操作记录。

## 快速开始

1. 准备 Node.js 和 Git，分别运行 `node --version`、`git --version` 检查是否可用。当前 Linux 实测为 Node.js v24.19.0、Git 2.52.0；没有声明最低兼容版本，Windows 原生运行仍待实机验证。安装请使用 [Node.js 官网](https://nodejs.org/) 和 [Git 官网](https://git-scm.com/)，工具不会替你安装。
2. 把本次完整交付文件放到一个新的独立目录。不要在原有业务仓库里覆盖文件、拉取或重置历史。若用 Git 获取，只克隆明确包含本次交付的版本到新目录；此说明不表示当前未发布改动已经上传。
3. 在工具目录打开终端，运行：

   ```sh
   npm start
   ```

4. 用这台电脑的浏览器打开 [真实工作台](http://127.0.0.1:4189/)。保持终端运行；停止时回到终端按 Ctrl+C，等待当前请求结束。

无需 `npm install`，运行只使用 Node 内置模块。也可在任意目录使用工具入口的绝对路径：

```sh
node /absolute/path/to/local-version-manager/server/index.js
```

只想看看界面，用 `npm run preview`，打开 [演示页面](http://127.0.0.1:4191/)。演示数据是虚构的，模拟操作刷新后重置，不访问真实仓库、材料或后端 API。不要把演示中的通过状态当成自己文件的检查结果。

## 现在可以做什么

| 功能 | 当前范围与验收状态 |
| --- | --- |
| 接入已有项目、查看状态和历史 | 已实现；接入只登记路径，不初始化、拉取或改写仓库历史 |
| 选择文件本地提交 | 已实现；必须先审查预览再确认，会真实写入当前分支。未选中的暂存内容受保护 |
| 安装包/升级包资料库、关联目录 | 已实现；扫描物理文件，分开显示来源声明、历史完整性和安装验证登记 |
| 单文件 SHA-256 与非覆盖归档 | 核心、HTTP API 和页面入口已实现；代码/API 独立审核完成，真实浏览器与 Windows 最终验收待完成 |
| 从独立目录、不同工作目录启动 | 已有 Linux 自动化验证，默认路径以工具目录为准 |
| Windows 与真实浏览器完整流程 | 待验，不宣称全平台或最终产品验收通过 |
| 推送、拉取、分支写操作、运行安装包、自动安装验证 | 本版不提供；本地跟踪引用仅是上次已有的快照 |

材料原文件不会因校验或归档被改写。真实确认会写工具操作记录；归档会在你确认的独立目标目录创建副本，因此本工具并非“完全只读”。算出摘要不等于可信、能安装或能升级。
